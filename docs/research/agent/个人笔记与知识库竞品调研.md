# 个人笔记与知识库功能竞品调研（含 NotebookLM Studio 机制）

> **类型**：非规范性研究材料（NON-NORMATIVE）
> **日期**：2026-08-11
> **范围**：个人笔记软件功能全景、GitHub 开源项目调研、Google NotebookLM Studio 机制、AigcForge Assistant 功能筛选
> **关联**：[个人助手智能体功能调研](个人助手智能体功能调研.md)、[个人智能体及桥接调研](个人智能体及桥接调研.md)、[AigcForge-双向链接与防幻觉机制调研](AigcForge-双向链接与防幻觉机制调研.md)、[Assistant PRD](../../prd/assistant-mode-personal-agent.md)
> **用途**：为 Assistant 模式的个人知识库（M2）与个人笔记/AI 产物生成（M2.5）提供功能依据

---

## 0. 摘要

1. **笔记竞争已从"编辑器"升级为"AI 原生知识引擎"**。NotebookLM 代表新物种：AI 严格基于用户上传的源文件作答（Grounding）、每句带可点击引文角标（Citation）、一键生成多种结构化产物（Studio）。
2. **双向链接是 PKM 类产品的行业标配**（Obsidian / Logseq / 思源 / Trilium / SilverBullet），是个人知识库的入门门槛，不是可选增强。
3. **极简速记与深度知识库是两种心智**：Flomo（零排版、随手记、随机反刍）vs Obsidian/Logseq（结构化关联、图谱探索）。AigcForge Assistant 用 AI 对话作统一入口，可同时覆盖两种心智。
4. **AigcForge 的差异化在于交叉点**：没有任何竞品同时拥有「双向链接 + AI 对话 + 持久调度器 + 联网搜索 + 代码工具链」。闪卡到期→收件箱提醒复习、每日随机反刍推送是纯笔记软件做不到的原生能力。

## 3. Google NotebookLM 深度调研（AI-First Grounded Notebook）

### 3.1 核心理念

严格限制 AI **仅基于用户上传的源文件**推理作答（Zero-Hallucination Grounding），从根源消除幻觉，实现 100% 观点溯源。与通用 ChatGPT/Claude 的全网检索有本质区别。

### 3.2 核心机制

| 机制 | 说明 | AigcForge 映射 |
|---|---|---|
| 多源数据锚定 | 单笔记本 ≤50 个源（PDF/Google Docs/Slides/TXT/Markdown/URL/YouTube/音频），跨文档交叉理解 | 用户问"我之前怎么处理 X 的？"→ 检索 kb_note + 记忆 → 仅基于这些内容作答 |
| 交互式引文溯源 | AI 每句带可点击数字角标 `[1][2]`，点击跳转到原始 PDF 段落/视频时间戳 | AI 回答带 `[笔记ID]` 角标 → 点击跳转笔记原文 |
| 音频/视觉概览 | AI 双人播客、思维导图、演示文稿草稿、视觉流程图 | 播客需 TTS 管线，**不采纳**；思维导图用 Mermaid（Work M3.5 已内联渲染） |
| 学习/研究产物生成 | Study Guide / FAQ / Timeline / Briefing Doc 一键生成 | 对应 propose_note 的 format 字段（study_guide/faq/timeline/briefing/summary/note/mindmap） |
| 云端代码沙盒 | 内置隔离 Python 执行，分析 CSV/表格 | AigcForge 已有 bash + Coding 模式，**不重复建设** |

### 3.3 三栏 UI

左栏 Sources（源文件管理 + 勾选参与对话）、中栏 Chat（基于源文件的问答）、右栏 Studio & Saved Notes（生成的产物 + 手写笔记卡片）。

### 4.2 应该做（M2.5 增强）

| 功能 | 参考 | 理由 |
|---|---|---|
| 日记页 Daily Notes | Obsidian/Logseq | 每日回顾高频场景 |
| 模板系统 | 思源/Logseq/Trilium/SilverBullet | 降低创建门槛 |

| **对话生成笔记 propose_note** | NotebookLM Studio | 复用 Chat propose 候选-审查-持久化链路 |
| **AI 源数据锚定问答 + 引文角标** | NotebookLM | 防幻觉证据链，对齐双向链接调研 |
| 笔记版本历史 | Trilium | diff + 回滚 |
| 别名 Aliases | Obsidian | 多标题链接 |
| 文件监听与索引重建 | Obsidian 文件系统 | 外部 Obsidian 编辑后自动同步 |

### 4.3 值得做（M3+）

| 功能 | 参考 | 理由 |
|---|---|---|
| 图谱视图 | Obsidian/Trilium/思源 | vis-network（Work M3.5 已内联） |
| 闪卡/间隔重复 | Logseq/思源 | 与提醒引擎联动：到期→收件箱提醒复习 |
| AI 产物生成 Studio | NotebookLM | 从笔记集合生成研究指南/FAQ/时间线/简报 |
| 块嵌入 | Logseq/思源 | `![[note-id#section]]` |
| 思维导图视图 | Trilium/AFFiNE | Mermaid 渲染 |
| 记忆↔笔记关系边 | NOOA Agent-Curated Store | supports/contradicts/derived_from 防幻觉 |
| 导出 Markdown/PDF/HTML | 所有 | 无锁定 |
| 随机反刍 | Flomo | Scheduler 每日随机推送一条历史笔记到收件箱 |

### 4.4 明确不做

| 功能 | 参考 | 排除理由 |
|---|---|---|
| AI 双人播客 | NotebookLM | 需 TTS 管线+脚本生成+双角色编排，独立产品线 |
| 云端代码沙盒 | NotebookLM | 已有 bash + Coding 模式 |
| 实时多人协同 | Notion/AppFlowy/AFFiNE | 个人开发者工具非团队平台 |
| 多视图数据库 | Notion/AppFlowy | 项目管理功能，Work Todo/Task 已覆盖 |
| 无限画布白板 | OneNote/AFFiNE/Canvas | 复杂度极高，与文字对话+笔记定位不符 |
| 1500+ 插件生态 | Obsidian | AigcForge 用 MCP/Skill 生态替代 |
| 块级双链（vs 文档级） | Logseq/思源 | M2 从文档级起步，M3 再引入块引用，复杂度可控 |

## 6. 对话生成笔记机制设计（propose_note）

### 6.1 复用现有链路

```
对话消息流 (SSE parts)
  -> extractMessageContent() 提取文本 [capture-helpers.ts]
  -> propose_note LLM 工具（新）候选稿 -> NoteCandidateInfo
  -> NoteCandidatePanel 右栏审查（Markdown 预览 + 标签 + 悬空链接提示）
  -> applyNoteCandidate() 调用 kb_create API 持久化
  -> kb_note 表 + <config>/knowledge-base/*.md 落盘
```

现有链路参考：[capture-helpers.ts](../../../packages/app/src/components/chat/capture-helpers.ts)、[work-asset-capture.ts](../../../packages/app/src/pages/work-asset-capture.ts)、[prompt-asset-candidate.ts](../../../packages/app/src/components/chat/prompt-asset-candidate.ts)、[suggestion-bar.tsx](../../../packages/app/src/components/chat/suggestion-bar.tsx)

### 6.2 propose_note 输入

| 字段 | 约束 |
|---|---|
| `title` | 1-80 字符 |
| `content` | Markdown 正文，含 `[[wikilink]]` |
| `tags` | 可选字符串数组 |
| `scope` | `global`（默认）/ `project` |
| `format` | `note`（默认）/ `summary` / `study_guide` / `faq` / `timeline` / `briefing` / `mindmap` |

### 6.3 format 产物类型

| format | NotebookLM 对应 | Assistant 场景 |
|---|---|---|
| note | 笔记卡片 | 从对话提取要点 |
| summary | 摘要 | 压缩整段对话 |
| study_guide | Study Guide | 概念+简答题 |
| faq | FAQ | 问答对整理 |
| timeline | Timeline | 事件排序 |
| briefing | Briefing Doc | 结构化汇报摘要 |
| mindmap | Mind Map | Mermaid mindmap 语法 |

### 6.4 触发方式

1. **AI 主动提议**：SuggestionBar 弹"这段讨论有价值，保存为笔记吗？"→ 用户确认 → propose_note
2. **用户主动指令**："把刚才讨论的整理成笔记"/"总结今天的对话"/"生成 FAQ"→ propose_note（带 format）
3. **快速捕获**："记一下：..."→ AI 生成极简笔记直接写入（可配置确认）
