## 最小实现合同

1. **公共保存按 Location。** canonical apply 移到 `/custom-profile/apply`，沿现 `WorkspaceRoutingQueryFields`、InstanceContext、WorkspaceRouting、Authorization 与实验开关。公开 canonical 调用不要求 SessionID。定位真实旧消费者后，一次确定旧 Session 路径兼容处置：有消费者则保留薄兼容入口，复用同一保存逻辑、位置决定、错误与开关；没有消费者则记录删除证据。兼容处理属于常规实现授权。delete 与其他资产 API 保持各自 owner，不扩成批量 CRUD 改造。
2. **同一根模型进入 Profile。** 使用 B06.1 最终 `Composition.BuiltinRoot`：`source: "builtin"`、`id: "build" | "plan" | "meta"`、`revision`。在 `CustomProfile.Profile.root` 引用此 Schema，不复制根类型。新保存链把有效 Temporary Plan 的规范 `plan.input.root` 写进 Candidate；显式保存根包含实际捕获 revision。Profile 持久化边界保证“显式根已捕获 revision”和“零用户池具有显式根”，最少用户 Agent 的旧规则仅对 root-less Profile 保持；上限仍为 16。
3. **旧数据保持原语义。** `root` 可缺省以读取既有 root-less Profile；不向旧 Profile/Input/snapshot 注入默认字段，也不重算或回写旧 digest。历史 root-less 零池仍拒绝。Candidate → Profile codec/YAML → registry Info.profile 必须保留根 source/id/revision；旧严格 MCP codec、凭据校验和已有引用字段继续沿现 owner。内置根不生成 Agent/Profile 占位文件，不写成用户 AgentRef 或 executorPreference。
4. **复用唯一保存事务。** 新文件 HTTP 省略 `baseRevision`，沿 handler 转成 Core 的 `null`；覆盖实际文件使用读回的 Profile revision 和现显式覆盖动作。复用现路径规范化、每路径锁、CAS、`FileMutation.writeAtomic`、写后读回、registry reload 和补偿。验证现编码通路；能自然透传的文件允许零生产差额。不得新增保存服务、文件缓存或一套 UI 摘要算法。
5. **两种 revision 说清对象。** [Profile revision](/home/keer/workspace/aigcfroge-v2/packages/core/src/custom-profile.ts:116) 是实际 YAML 字节 revision，决定文件 CAS 和 `ProfileInput.profileRevision`；[保存读回比较](/home/keer/workspace/aigcfroge-v2/packages/core/src/custom-profile-service.ts:321) 裁定 registry revision 是否与所写字节一致。[root revision](/home/keer/workspace/aigcfroge-v2/packages/core/src/composition-resolver.ts:622) 是 B06.1 同一 canonical Agent.Info 冻结定义的 revision，[snapshot 核验](/home/keer/workspace/aigcfroge-v2/packages/core/src/session/composition.ts:553) 比较冻结值。UI 同时显示 Profile path/revision 与所选根/定义 revision。Meta 渲染和根 revision 计算复用这些决定函数，不能改成裸 ID、当前版本字符串或新的 hash owner。
6. **Profile source 消费保存根。** Resolver 从已读取的 `profile.profile.root` 取 declaredRoot，沿同一根可用性、身份冲突、资产诊断、Meta 条件渲染和 revision 核验。有效 Profile Plan 的规范输入继续是现 [ProfileInput](/home/keer/workspace/aigcfroge-v2/packages/schema/src/composition.ts:162)，不额外发明 top-level root。freeze 将本次实际解析且核验的 Profile 根写入已有 `SnapshotDataV2.root`，并保留 profilePath/profileRevision/sourceLocation。缺失或漂移产生现类型化诊断，不静默换根。
7. **显式采用沿既有出口。** 同 Location 调用 [plan/start](/home/keer/workspace/aigcfroge-v2/packages/protocol/src/groups/custom-composition.ts:39)。Profile 预览输入为 `{ source: "profile", profilePath: saved.relativePath, profileRevision: saved.revision }`；确认使用返回的规范 `plan.input` 和 `expectedPlanDigest: plan.digest`，由 [start digest 比较](/home/keer/workspace/aigcfroge-v2/packages/core/src/session.ts:653) 裁定。确认身份只捕获一次；失败重试沿首片 [exact retry 比较](/home/keer/workspace/aigcfroge-v2/packages/core/src/session.ts:613)。Created commit、snapshot、Permission、Session readback、普通 fork 和执行消费复用现 owner。已有 [retry 根选择](/home/keer/workspace/aigcfroge-v2/packages/core/src/session.ts:610) 与 [fork 根选择](/home/keer/workspace/aigcfroge-v2/packages/core/src/session.ts:1014) 从 snapshot 取根，无需重做；仅修复本通路确定的实际漏消费。
8. **定义变动不改已采用身份。** 保存后到预览/确认之间发生 Profile 或根漂移时，释放旧预览并显示具体冲突；用户明确重读/预览后再采用。已采用 Session 的冷读、exact retry、普通 fork 保留原根、来源 Profile revision 和 snapshot，后续保存不自动升级它。非 Meta 根继续没有 Meta controller/association。当前权限逐次执行仍由现 Permission owner 决定。
