## 1. Claude Artifacts（Anthropic）✅ 已核验

### 1.1 定位
**数字资产分发与多格式实时渲染沙箱**。打破 Chat 界面"单向滚动文本流"局限，将可复用、独立成件的内容（200+ 行代码、复杂 SVG、Mermaid 架构图、交互 React 工具）从对话流剥离，提升为独立可交互的数字资产（Digital Artifacts）。**正是用户想要的"格式无关预览 Tab"方向**。

### 1.2 MIME-Type 驱动的分发渲染

LLM 产出 `<antArtifact>` 结构化标签（API 中为 `antml:artifact`），含显式 `type` 字段（MIME-Type）。前端识别后分发至不同 Renderer：

| MIME-Type | 格式 | 渲染方式 |
|---|---|---|
| `application/vnd.ant.react` | React 组件 | 解构编译 JSX/TSX，运行在**内置 React 运行时**中 |
| `text/html` | HTML 页面 | 单文件 HTML/CSS/JS 页面渲染（iframe sandbox） |
| `application/vnd.ant.mermaid` | Mermaid | 解析 Mermaid 语法，Client 端直接绘制 SVG |
| `image/svg+xml` | SVG | 原生渲染矢量图（响应式 viewBox 适配） |
| `text/markdown` | Markdown | Markdown 渲染器 |
| `application/vnd.ant.code` | 代码 | 语法高亮 |

**这是格式路由（renderer registry）的工业级实现**--MIME-Type 显式声明，前端按 type 分发。AigcForge 可借鉴此模式（用 fenced code block 语言标或显式 type 标记）。

### 1.3 安全模型：严格的前端 iframe 沙箱

- **客户端 iframe sandbox**（`sandbox="allow-scripts"`，**绝不加** `allow-same-origin`）--null origin 隔离父页面 DOM/Cookie
- **禁用 localStorage/sessionStorage**：iframe 内不可持久化存储，必须通过 React 内存状态（useState）控制--防止恶意 JS 持久化 payload 或跨会话留存数据
- **严格 CSP**：禁用未授权外部 API 请求 / 任意跨域 Fetch，防恶意代码注入
- **预置白名单 CDN**（如 cdnjs）+ 常用 UI 库生态：Tailwind CSS、Lucide React、Recharts、Shadcn/UI
- **React 运行时预打包**：组件不能用任意 npm 包，只能用白名单库

### 1.4 单文件自包含约束

为保证快速即时预览，Claude 生成组件要求**尽量打包在单文件/单组件**中。外部图片通常推荐**转换为 Base64 内嵌**（避免外部资源依赖 + CSP 限制）。

### 1.5 对 M3.5 的借鉴价值：⭐⭐⭐⭐⭐（最高）
- MIME-Type 驱动的格式路由 = renderer registry 工业范式
- 浏览器 iframe srcdoc + `allow-scripts`（无 same-origin）= AigcForge 本地优先桌面的最佳安全模型
- 白名单库预打包（非任意 npm install）= 安全 + 包体可控
- 单文件自包含 + Base64 图片 = 离线可用 + CSP 友好

## 2. E2B Fragments（开源，代码核验）

### 2.1 定位
[E2B Fragments](https://github.com/e2b-dev/fragments) 是 Claude Artifacts / v0 / GPT Engineer 的**开源复刻**。Next.js 14 + Vercel AI SDK + shadcn/ui。用 [E2B SDK](https://github.com/e2b-dev/code-interpreter) 在**云端 Docker 沙箱**执行 LLM 生成代码。

### 2.2 渲染架构（代码核验）

**结构化输出**（[lib/schema.ts](https://github.com/e2b-dev/fragments/blob/main/lib/schema.ts) Zod schema）：LLM 产 `fragmentSchema`（template + code + deps + port + file_path），Vercel AI SDK `streamObject` 流式。

**格式路由**（[fragment-preview.tsx](https://github.com/e2b-dev/fragments/blob/main/components/fragment-preview.tsx)）--**renderer registry 模式**：
```tsx
if (getTemplateId(result.template) === 'code-interpreter-v1') {
  return <FragmentInterpreter result={result} />  // Python stdout
}
return <FragmentWeb result={result} />  // iframe 预览
```

**Web 预览 iframe**（[fragment-web.tsx](https://github.com/e2b-dev/fragments/blob/main/components/fragment-web.tsx)）：
```tsx
<iframe
  sandbox="allow-forms allow-scripts allow-same-origin"  // ⚠️ 含 allow-same-origin
  src={result.url}  // 指向 E2B 云沙箱 URL（非 srcdoc）
/>
```

**两 Tab 布局**（[preview.tsx](https://github.com/e2b-dev/fragments/blob/main/components/preview.tsx)）：Code（源码）+ Preview（渲染）。

### 2.3 安全模型
- 代码在 E2B **云 Docker 沙箱**执行（非浏览器）
- iframe `src={sandbox_url}` 指向云沙箱（**非 srcdoc 内联**）
- `allow-same-origin`：因沙箱是独立 origin 的真实服务器，需保留 origin 让 web app 正常工作
- 依赖安装：LLM 声明 `additional_dependencies`，沙箱内 `npm install` / `pip install`

### 2.4 对 M3.5 的借鉴价值：⭐⭐⭐⭐（高）
- **格式路由模式**直接可借
- **结构化输出**（Zod schema）可借
- **两 Tab 布局**与 AigcForge WorkArtifactContent 接近
- **云沙箱 + allow-same-origin 不借**--AigcForge 共享 app origin，allow-same-origin = XSS 升级

## 3. ChatGPT Canvas（OpenAI）✅ 已核验

### 3.1 定位
**AI 驱动的实时协同编辑器（Co-editor）**。打破 AI 只能"在对话框底部追加回答"的模式：对话框=控制面板，右侧 Canvas=持久化状态文本/代码画布。**非渲染器，是编辑器**--但其交互模式对 Work 模式有直接借鉴价值。

### 3.2 核心机制

**1. 选区驱动的局部 Patch（Highlight-to-edit）**：
- 传统缺陷：改一个错别字，AI 重写 500 字，耗时且打断思路
- Canvas 创新：用户选中任意文本/代码行 -> 唤起 Inline Prompt 框 -> GPT-4o 仅针对高亮选区分析并施加 Patch（增量替换）
- **极速局部修饰**，非全量重写

**2. 分场景辅助捷径（Quick Actions Menu）**：
- 文本模式：Reading Level（阅读难度切换）/ Adjust Length（篇幅伸缩）/ Add Polish / Final Grammar Check
- 代码模式：Code Review（侧边批注）/ Add Logs / Inline Comments / Fix Bugs / Port Language（语言翻译）

**3. 版本滑块与差异对比（Version History & Slider）**：
- Git 式版本回滚：拖动滑块查看历史修改记录
- 支持随时恢复到任意历史快照

**4. 2026 演进趋势**：OpenAI 逐步将 Canvas 侧边栏编辑能力**融入主对话流的动态交互卡片**中（不再独立侧栏），降低上下文切换成本。

### 3.3 对 M3.5 的借鉴价值：⭐⭐⭐（中--非 M3.5 范围，但属未来 Work 增强）

**Canvas 不是渲染器**（无 HTML/交互预览），其价值在**交互编辑模式**：
- **Highlight-to-edit**：AigcForge Work 当前 step 6 "Revise on request: rewrite the full candidate" 是**全量重写**。Canvas 的局部 Patch 是更优 UX--用户选中段落 -> 局部修改，不重写全文
- **Quick Actions**：润色/扩写/翻译 等快捷按钮，对 Work 文档编辑直接适用
- **Version History**：与 M1.5 ProgressLedger + task outputDigest 结合，可做版本滑块 + Diff 预览 + Revert

**⚠️ 范围澄清**：这些是**未来 Work 模式交互增强**（可能的 M4/M5 方向），**不属于 M3.5 渲染范畴**。M3.5 聚焦"产出预览"，Canvas 聚焦"编辑迭代"--两者正交。

## 4. Vercel v0（Vercel）✅ 已核验

### 4.1 定位
**全栈 AI Web 工程师**。不止静态组件渲染，直接打通 Modern Web 全栈（React / Next.js / Tailwind / Shadcn UI / Node.js 运行时）。

### 4.2 核心机制

**1. Vercel Sandbox（Firecracker microVM 虚拟机沙箱）**：
- 区别于 Artifacts 的**前端沙箱**：v0 在后端为每个 Session 启动独立 Firecracker 微型虚拟机（**Kernel-level Isolation**）
- 全栈执行：Node.js 服务、`pnpm install` 任意依赖、Next.js App Router API 路由、连接 SQLite/PostgreSQL

**2. 深度生态绑定（Component-First 范式）**：
- Shadcn/UI 深度适配：生成代码不是封闭组件，是**完全展开的 Tailwind + Radix 原生代码**（符合生产级规范）
- 不是"组件黑盒"，开发者可直接接手

**3. 视觉元素点选（Visual Element Inspector）**：
- 用户在 Preview 面板直接点击任意 Button/Card 元素
- 高亮对应代码段
- 对选定元素提修改意见（如"按钮改天蓝色 + Hover 动画"）

**4. 工程化产出闭环（Production-Ready Workflow）**：
- 一键部署至 Vercel 生产环境 URL
- 同步代码仓库至 GitHub
- 本地 `npx v0 add` 直接拉取到工程

### 4.3 对 M3.5 的借鉴价值：⭐⭐（低--不借鉴云架构）

- **Firecracker microVM 不借**：AigcForge 本地优先桌面，不依赖云虚拟机
- **Visual Element Inspector**（点选元素 -> 高亮代码 -> 修改）：远期可参考（若 M3.5 HTML 预览支持元素点选编辑），但非 M3.5 核心范围
- **生产级代码产出**思路：v0 强调"产出可用代码"，AigcForge Work 候选稿也是"产出可用文档/HTML"--理念一致，但 Work 不做一键 Deploy
- **流式预览**：v0 边生成边预览；AigcForge 先做完整产出后预览（M1 模式），流式远期

### 5.1 三条演进方向（战略框架）

对比三产品，AigcForge Work 模式可提炼**三条平行演进方向**：

| 方向 | 借鉴源 | 当前 AigcForge | 演进目标 | 归属 |
|---|---|---|---|---|
| **① 渲染增强** | Claude Artifacts | Markdown + Mermaid（M1/M3 L1） | 多格式 Artifact 沙箱（HTML/SVG/未来 React） | **M3.5（本调研）** |
