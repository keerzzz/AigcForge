# docs/audit

全量代码审计报告归档。

## 与 `docs/review/` 的区别

| | `docs/review/` | `docs/audit/`（本目录） |
|---|---|---|
| 对象 | 一次改动（diff / PR / 分支） | 一个已存在的代码族 |
| 触发 | 提交前 / 合并前 | 专项质量排查、发布前体检 |
| 基准 | 与 main 的差异 | 已批准的 PRD / ADR 不变量 |
| 结论 | 是否可合并 | 缺陷清单 + 根因收敛 + 协议合规缺口 |

diff 级审查看"这次改动有没有引入问题"，全量审计看"这个子系统现在是否仍然兑现它的契约"。两者互补：审计能发现门禁全绿但契约已失效的缺陷。

## 命名约定

`AigcForge_<SCOPE>_AUDIT_<YYYY-MM-DD>.md`，与 `docs/review/` 的前缀风格对齐。

## 报告应包含

1. 基线声明（提交 hash、门禁结果、意图来源文档）
2. 方法与**覆盖度声明**（含未覆盖范围，如实列出）
3. 缺陷清单（编号 + 严重度 + 位置 + 触发路径 + 证据）
4. **根因收敛**（按 `CLAUDE.md` 收敛三步法，不逐条列现象）
5. 协议合规映射（区分"明文违反"与"协议盲区"）
6. 文档-代码事实偏差
7. 已核查确认无问题的点（避免重复审计）

每条缺陷必须能写出具体触发路径；写不出的降级为代码异味，不计入缺陷数。
