---
title: ポリシー
description: Aigcfroge が使用できる設定済みリソースを制御します。
---

ポリシーは、Aigcfroge が名前付きリソースに対してアクションを実行できるかどうかを制御します。この機能は実験的なものであり、`aigcfroge.json` の `experimental.policies` 配列で設定されます。

ポリシーは[権限](/docs/permissions)とは別のものです。権限はセッション中にツールが実行できることを制御し、ポリシーは Aigcfroge が LLM プロバイダーなどのリソースを使用できるかどうかを制御します。

---

## 設定

各ポリシーステートメントには 3 つのフィールドがあります。

- `effect` - `"allow"` または `"deny"` のいずれか。
- `action` - 制御される操作。
- `resource` - ステートメントが適用されるリソース ID またはワイルドカードパターン。

たとえば、`openai` プロバイダーの使用を拒否するには、次のようにします。

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

ポリシーによって拒否されたプロバイダーは、認証情報がある場合や正しく設定されている場合でも、モデル選択やモデルの使用には利用できません。

---

## 利用可能なポリシー

Aigcfroge は現在、1 つのポリシーアクションをサポートしています。

| アクション      | リソース                       | 説明                                |
| -------------- | ----------------------------- | ------------------------------------- |
| `provider.use` | `openai` などのプロバイダー ID | LLM プロバイダーの使用を許可または拒否します。 |

将来、さらに多くのポリシーアクションが追加される可能性があります。

---

## マッチング

`resource` フィールドはワイルドカードマッチングをサポートしています。`*` を使用して 0 個以上の任意の文字に一致させ、`?` を使用して 1 文字に一致させます。

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "company-*"
      }
    ]
  }
}
```

これにより、`company-us` や `company-eu` などのプロバイダーが拒否されます。

---

## ルールの順序

複数のステートメントが一致する場合、最後に一致したステートメントが優先されます。広いルールを最初に置き、その後に特定の例外を配置します。

たとえば、Anthropic のみを許可するには、次のようにします。

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "*"
      },
      {
        "effect": "allow",
        "action": "provider.use",
        "resource": "anthropic"
      }
    ]
  }
}
```

ポリシーがプロバイダーに一致しない場合、プロバイダーの使用はデフォルトで許可されます。

ポリシーは、グローバル設定とプロジェクト設定の両方に設定できます。両方の場所のポリシーが同じプロバイダーに一致する場合、グローバルポリシーがプロジェクトポリシーより優先されます。これにより、グローバルに拒否したプロバイダーをリポジトリが再度有効化することを防ぎます。

---

## プロバイダーリスト

プロバイダーへのアクセスを制御する場合は、古い `disabled_providers` および `enabled_providers` 設定の代わりにポリシーを使用してください。

`disabled_providers` を置き換えるには、次のようにします。

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "openai" },
      { "effect": "deny", "action": "provider.use", "resource": "google" }
    ]
  }
}
```

`enabled_providers` を置き換えるには、最初にすべてのプロバイダーを拒否し、その後に選択したプロバイダーを許可します。

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "*" },
      { "effect": "allow", "action": "provider.use", "resource": "anthropic" },
      { "effect": "allow", "action": "provider.use", "resource": "openai" }
    ]
  }
}
```
