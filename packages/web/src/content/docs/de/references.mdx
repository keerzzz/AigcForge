---
title: Referenzen
description: Fügen Sie lokale Verzeichnisse und Git-Repositorys als Projektreferenzen hinzu.
---

Referenzen geben Aigcfroge Zugriff auf Verzeichnisse außerhalb des aktuellen Projekts. Verwenden Sie sie, um Dokumentation, gemeinsame Bibliotheken, Beispiele oder ein anderes Repository während Ihrer Arbeit verfügbar zu machen.

Referenzen werden per Alias in `aigcfroge.json` oder `aigcfroge.jsonc` konfiguriert.

```jsonc title="aigcfroge.jsonc"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and documentation conventions",
    },
    "sdk": {
      "repository": "keerzzz/AigcForge-sdk-js",
      "branch": "main",
      "description": "Use for JavaScript SDK implementation details",
    },
  },
}
```

---

## Lokale Verzeichnisse

Verwenden Sie `path`, um auf ein lokales Verzeichnis zu verweisen.

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "docs": {
      "path": "../docs",
    },
  },
}
```

Pfade können sein:

- Relativ zur Konfigurationsdatei, die die Referenz definiert
- Absolut, z. B. `/home/user/docs`
- Relativ zu Ihrem Home-Verzeichnis, z. B. `~/docs`

Sie können auch eine String-Kurzform verwenden:

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "docs": "../docs",
  },
}
```

## Git-Repositorys

Verwenden Sie `repository`, um auf ein Git-Repository zu verweisen. Aigcfroge materialisiert das Repository in seinem lokalen Repository-Cache und stellt den ausgecheckten Quellcode als Referenzverzeichnis bereit.

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main",
    },
  },
}
```

`repository` akzeptiert Git-URLs, Host/Pfad-Referenzen und die GitHub-Kurzform `owner/repo`. Das optionale Feld `branch` wählt einen Branch oder Ref aus. Ohne `branch` verwendet Aigcfroge den Standard-Branch des Repositorys.

Sie können die String-Kurzform verwenden, wenn Sie keinen Branch, keine Beschreibung oder keine anderen Optionen benötigen:

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "effect": "Effect-TS/effect",
  },
}
```

:::note
Git-Referenzen werden asynchron aktualisiert. Ein neu konfiguriertes Repository kann einen Moment benötigen, um das Klonen oder Aktualisieren abzuschließen.
:::

## Verwendung beschreiben

Fügen Sie `description` hinzu, um zu erklären, wann ein Agent eine Referenz verwenden sollte.

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "design-system": {
      "path": "../design-system",
      "description": "Use when implementing UI components or design tokens",
    },
  },
}
```

Aigcfroge nimmt Referenzen mit Beschreibungen in den Agentenkontext auf. Beschreibungen sollten kurz und spezifisch genug sein, um Referenzen mit ähnlichem Inhalt zu unterscheiden. Referenzen ohne Beschreibungen bleiben über die Autovervollständigung und die direkte Verwendung verfügbar, werden aber nicht an Agenten weitergegeben.

---

## Autovervollständigungs-Einträge ausblenden

Setzen Sie `hidden` auf `true`, um eine Referenz aus der `@`-Autovervollständigung in der TUI auszublenden.

```jsonc title="aigcfroge.jsonc"
{
  "references": {
    "internal": {
      "path": "../internal",
      "description": "Use for internal implementation details",
      "hidden": true,
    },
  },
}
```

`hidden` betrifft nur die Autovervollständigung. Eine ausgeblendete Referenz mit einer Beschreibung bleibt im Agentenkontext enthalten.

---

## Referenzen verwenden

Konfigurierte Referenzen erscheinen in der `@`-Autovervollständigung der TUI. Geben Sie `@alias` ein, um das Referenzverzeichnis anzuhängen, oder `@alias/`, um nach Dateien darin zu suchen.

```text
Compare this implementation with @sdk/src/client.ts
```

Agenten erhalten außerdem die aufgelösten Pfade und Beschreibungen der konfigurierten Referenzen, die über Beschreibungen verfügen, in ihrem Systemkontext. So können sie eine Referenz prüfen, wenn sie relevant ist, ohne dass Sie sie manuell anhängen.

Aigcfroge erlaubt Referenzverzeichnisse automatisch über seine Berechtigungsgrenze für externe Verzeichnisse. Die normalen Tool-Berechtigungen gelten weiterhin; so erhält beispielsweise ein Agent, der keine Dateien bearbeiten kann, keine Bearbeitungsrechte, nur weil ein Verzeichnis als Referenz konfiguriert ist.

## Konfigurierbare Felder

| Feld         | Lokal | Git | Beschreibung                                      |
| ------------ | ----- | --- | ------------------------------------------------- |
| `path`        | Ja    | Nein | Lokales Referenzverzeichnis                       |
| `repository`  | Nein  | Ja  | Git-URL, Host/Pfad oder GitHub-`owner/repo`-Wert |
| `branch`      | Nein  | Ja  | Optionaler Git-Branch oder Ref                    |
| `description` | Ja    | Ja  | Hinweise, wann die Referenz verwendet werden soll |
| `hidden`      | Ja    | Ja  | Referenz aus der `@`-Autovervollständigung der TUI ausblenden |

Referenzaliase dürfen nicht leer sein und keine `/`, Leerzeichen, Backticks oder Kommas enthalten.
