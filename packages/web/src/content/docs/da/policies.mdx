---
title: Politikker
description: Kontroller, hvilke konfigurerede ressourcer Aigcfroge må bruge.
---

Politikker styrer, om Aigcfroge må udføre en handling på en navngivet ressource. Denne funktion er eksperimentel og konfigureres med `experimental.policies`-arrayet i `aigcfroge.json`.

Politikker er adskilt fra [tilladelser](/docs/permissions). Tilladelser styrer, hvad værktøjer kan gøre under en session, mens politikker styrer, om Aigcfroge må bruge en ressource såsom en LLM-udbyder.

---

## Konfiguration

Hver politik-sætning har tre felter:

- `effect` - Enten `"allow"` eller `"deny"`.
- `action` - Den handling, der styres.
- `resource` - Ressource-ID'et eller jokertegnsmønstret, som sætningen gælder for.

Du kan for eksempel nægte brug af `openai`-udbyderen:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

En udbyder, der nægtes af en politik, er ikke tilgængelig til modelvalg eller modelbrug, selvom den har legitimationsoplysninger eller ellers er korrekt konfigureret.

---

## Tilgængelige politikker

Aigcfroge understøtter i øjeblikket én politik-handling:

| Handling      | Ressource                      | Beskrivelse                               |
| -------------- | ----------------------------- | ----------------------------------------- |
| `provider.use` | Udbyder-id, såsom `openai` | Tillad eller nægt brug af en LLM-udbyder. |

Flere politik-handlinger kan blive tilføjet i fremtiden.

---

## Matchning

Feltet `resource` understøtter jokertegn-matchning. Brug `*` til at matche nul eller flere tegn og `?` til at matche ét tegn.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "company-*"
      }
    ]
  }
}
```

Dette nægter udbydere såsom `company-us` og `company-eu`.

---

## Reglers rækkefølge

Når flere sætninger matcher, vinder den sidst matchende sætning. Sæt brede regler først og mere specifikke undtagelser bagefter.

Tillad for eksempel kun Anthropic:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "*"
      },
      {
        "effect": "allow",
        "action": "provider.use",
        "resource": "anthropic"
      }
    ]
  }
}
```

Hvis ingen politik matcher en udbyder, er udbyderbrug tilladt som standard.

Politikker kan angives i både din globale konfiguration og projektkonfiguration. Hvis politikker fra begge steder matcher den samme udbyder, har din globale politik forrang frem for projektpolitikken. Dette forhindrer, at et repository genaktiverer en udbyder, som du nægter globalt.

## Lister over udbydere

Brug politikker i stedet for de ældre `disabled_providers`- og `enabled_providers`-indstillinger, når du styrer udbyderadgang.

For at erstatte `disabled_providers`:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "openai" },
      { "effect": "deny", "action": "provider.use", "resource": "google" }
    ]
  }
}
```

For at erstatte `enabled_providers` skal du først nægte alle udbydere og derefter tillade de valgte udbydere:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "*" },
      { "effect": "allow", "action": "provider.use", "resource": "anthropic" },
      { "effect": "allow", "action": "provider.use", "resource": "openai" }
    ]
  }
}
```
