---
title: Policy
description: Controlla quali risorse configurate Aigcfroge puo usare.
---

Le policy controllano se Aigcfroge puo eseguire un'azione su una risorsa nominata. Questa funzionalita e sperimentale e viene configurata con l'array `experimental.policies` in `aigcfroge.json`.

Le policy sono separate dai [permessi](/docs/permissions). I permessi controllano cosa possono fare gli strumenti durante una sessione, mentre le policy controllano se Aigcfroge puo usare una risorsa come un provider LLM.

---

## Configurazione

Ogni regola di policy ha tre campi:

- `effect` - O `"allow"` o `"deny"`.
- `action` - L'operazione controllata.
- `resource` - L'ID della risorsa o il pattern con wildcard a cui si applica la regola.

Per esempio, nega l'uso del provider `openai`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

Un provider negato dalla policy non e disponibile per la selezione o l'uso dei modelli, anche se ha le credenziali o e comunque configurato correttamente.

---

## Policy disponibili

Aigcfroge supporta attualmente un'azione di policy:

| Azione         | Risorsa                     | Descrizione                            |
| -------------- | --------------------------- | -------------------------------------- |
| `provider.use` | ID del provider, ad es. `openai` | Consenti o nega l'uso di un provider LLM. |

Altre azioni di policy potrebbero essere aggiunte in futuro.

---

## Corrispondenza

Il campo `resource` supporta il matching con wildcard. Usa `*` per corrispondere a zero o piu caratteri e `?` per corrispondere a un singolo carattere.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "company-*"
      }
    ]
  }
}
```

Questo nega provider come `company-us` e `company-eu`.

---

## Ordine delle regole

Quando piu regole corrispondono, vince l'ultima che corrisponde. Metti prima le regole generali e poi le eccezioni piu specifiche dopo di esse.

Per esempio, consenti solo Anthropic:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "*"
      },
      {
        "effect": "allow",
        "action": "provider.use",
        "resource": "anthropic"
      }
    ]
  }
}
```

Se nessuna policy corrisponde a un provider, l'uso del provider e consentito per impostazione predefinita.

Le policy possono essere impostate sia nella configurazione globale sia in quella di progetto. Se le policy di entrambe le posizioni corrispondono allo stesso provider, la tua policy globale ha la priorita su quella di progetto. Questo impedisce a un repository di riabilitare un provider che neghi a livello globale.

## Elenchi di provider

Usa le policy invece delle piu vecchie impostazioni `disabled_providers` e `enabled_providers` quando controlli l'accesso ai provider.

Per sostituire `disabled_providers`:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "openai" },
      { "effect": "deny", "action": "provider.use", "resource": "google" }
    ]
  }
}
```

Per sostituire `enabled_providers`, nega prima tutti i provider e consenti poi quelli selezionati:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "*" },
      { "effect": "allow", "action": "provider.use", "resource": "anthropic" },
      { "effect": "allow", "action": "provider.use", "resource": "openai" }
    ]
  }
}
```
