title: Агенти
description: Налаштовуйте та використовуйте спеціалізованих агентів.
---

Агенти — це спеціалізовані AI-помічники, які можна налаштувати для конкретних завдань і робочих процесів. Вони дають змогу створювати спеціалізовані інструменти з власними промптами, моделями та доступом до інструментів.

:::tip
Використовуйте агента plan, щоб аналізувати код і переглядати пропозиції, не вносячи жодних змін у код.
:::

Під час сесії ви можете перемикатися між агентами або викликати їх через згадку `@`.

---

## Типи

В Aigcfroge існує два типи агентів: основні агенти та субагенти.

---

### Основні агенти

Основні агенти — це головні помічники, з якими ви взаємодієте безпосередньо. Ви можете перемикатися між ними за допомогою клавіші **Tab** або налаштованої прив'язки `switch_agent`. Ці агенти ведуть вашу основну розмову. Доступ до інструментів налаштовується через дозволи — наприклад, у Build увімкнено всі інструменти, тоді як Plan обмежений.

:::tip
Ви можете використовувати клавішу **Tab**, щоб перемикатися між основними агентами під час сесії.
:::

Aigcfroge постачається з двома вбудованими основними агентами — **Build** та **Plan**. Ми розглянемо їх нижче.

---

### Субагенти

Субагенти — це спеціалізовані помічники, яких основні агенти можуть викликати для конкретних завдань. Ви також можете викликати їх вручну, **згадавши** їх через `@` у своїх повідомленнях.

Aigcfroge постачається з трьома вбудованими субагентами — **General**, **Explore** та **Scout**. Ми розглянемо їх нижче.

---

## Вбудовані

Aigcfroge постачається з двома вбудованими основними агентами та трьома вбудованими субагентами.

---

### Використання build

_Режим_: `primary`

Build — це **типовий** основний агент з усіма ввімкненими інструментами. Це стандартний агент для роботи над розробкою, де потрібен повний доступ до операцій із файлами та системних команд.

---

### Використання plan

_Режим_: `primary`

Обмежений агент, призначений для планування та аналізу. Ми використовуємо систему дозволів, щоб дати вам більше контролю та запобігти ненавмисним змінам.
За замовчуванням усі наведені нижче значення встановлені на `ask`:

- `file edits`: усі записи, патчі та редагування
- `bash`: усі bash-команди

Цей агент корисний, коли ви хочете, щоб LLM аналізував код, пропонував зміни або створював плани, не вносячи жодних реальних модифікацій у вашу кодову базу.

---

### Використання general

_Режим_: `subagent`

Універсальний агент для дослідження складних питань і виконання багатокрокових завдань. Має повний доступ до інструментів (крім todo), тож може вносити зміни у файли, коли це потрібно. Використовуйте його, щоб виконувати кілька одиниць роботи паралельно.

---

### Використання explore

_Режим_: `subagent`

Швидкий агент лише для читання, призначений для дослідження кодових баз. Не може змінювати файли. Використовуйте його, коли потрібно швидко знайти файли за шаблонами, шукати код за ключовими словами або відповідати на питання про кодову базу.

---

### Використання scout

_Режим_: `subagent`

Агент лише для читання, призначений для зовнішньої документації та дослідження залежностей. Використовуйте його, коли потрібно клонувати репозиторій залежності в керований кеш Aigcfroge, переглядати вихідний код бібліотеки або звіряти локальний код з реалізаціями upstream, не змінюючи вашу робочу область.

---

### Використання compaction

_Режим_: `primary`

Прихований системний агент, який ущільнює довгий контекст у коротший підсумок. Він запускається автоматично, коли це потрібно, і його не можна вибрати в інтерфейсі.

---

### Використання title

_Режим_: `primary`

Прихований системний агент, який генерує короткі назви сесій. Він запускається автоматично, і його не можна вибрати в інтерфейсі.

---

### Використання summary

_Режим_: `primary`

Прихований системний агент, який створює підсумки сесій. Він запускається автоматично, і його не можна вибрати в інтерфейсі.

---

## Використання

1. Для основних агентів використовуйте клавішу **Tab**, щоб перемикатися між ними під час сесії. Також можна використовувати налаштовану прив'язку `switch_agent`.

2. Субагентів можна викликати:
   - **Автоматично** — основними агентами для спеціалізованих завдань на основі їхніх описів.
   - Вручну — **згадавши** субагента через `@` у своєму повідомленні. Наприклад.

     ```txt frame="none"
     @general help me search for this function
     ```

3. **Навігація між сесіями**: коли субагенти створюють дочірні сесії, використовуйте `session_child_first` (за замовчуванням: **\<Leader>+Down**), щоб увійти в першу дочірню сесію з батьківської.

4. Коли ви в дочірній сесії, використовуйте:
   - `session_child_cycle` (за замовчуванням: **Right**), щоб перейти до наступної дочірньої сесії
   - `session_child_cycle_reverse` (за замовчуванням: **Left**), щоб перейти до попередньої дочірньої сесії
   - `session_parent` (за замовчуванням: **Up**), щоб повернутися до батьківської сесії

   Це дає змогу перемикатися між основною розмовою та спеціалізованою роботою субагента.

## Конфігурування

Ви можете налаштувати вбудованих агентів або створити власних через конфігурацію. Агентів можна налаштувати двома способами:

---

### JSON

Налаштуйте агентів у вашому конфігураційному файлі `aigcfroge.json`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "agent": {
    "build": {
      "mode": "primary",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "{file:./prompts/build.txt}",
      "permission": {
        "edit": "allow",
        "bash": "allow"
      }
    },
    "plan": {
      "mode": "primary",
      "model": "anthropic/claude-haiku-4-20250514",
      "permission": {
        "edit": "deny",
        "bash": "deny"
      }
    },
    "code-reviewer": {
      "description": "Reviews code for best practices and potential issues",
      "mode": "subagent",
      "model": "anthropic/claude-sonnet-4-20250514",
      "prompt": "You are a code reviewer. Focus on security, performance, and maintainability.",
      "permission": {
        "edit": "deny"
      }
    }
  }
}
```

---

### Markdown

Ви також можете визначати агентів за допомогою markdown-файлів. Розмістіть їх у:

- Глобально: `~/.config/aigcfroge/agents/`
- Для проєкту: `.aigcfroge/agents/`

```markdown title="~/.config/aigcfroge/agents/review.md"
---
description: Reviews code for quality and best practices
mode: subagent
model: anthropic/claude-sonnet-4-20250514
temperature: 0.1
permission:
  edit: deny
  bash: deny
---

You are in code review mode. Focus on:

- Code quality and best practices
- Potential bugs and edge cases
- Performance implications
- Security considerations

Provide constructive feedback without making direct changes.
```

Назва markdown-файлу стає назвою агента. Наприклад, `review.md` створює агента `review`.

---

## Опції

Розглянемо ці параметри конфігурації детальніше.

---

### Опис

Використовуйте опцію `description`, щоб надати короткий опис того, що робить агент і коли його слід використовувати.

```json title="aigcfroge.json"
{
  "agent": {
    "review": {
      "description": "Reviews code for best practices and potential issues"
    }
  }
}
```

Це **обов'язкова** опція конфігурації.

---

### Температура

Керуйте випадковістю та креативністю відповідей LLM за допомогою конфігурації `temperature`.

Нижчі значення роблять відповіді більш зосередженими та детермінованими, тоді як вищі значення підвищують креативність і варіативність.

```json title="aigcfroge.json"
{
  "agent": {
    "plan": {
      "temperature": 0.1
    },
    "creative": {
      "temperature": 0.8
    }
  }
}
```

Значення температури зазвичай коливаються від 0.0 до 1.0:

- **0.0-0.2**: дуже зосереджені та детерміновані відповіді, ідеально для аналізу коду та планування
- **0.3-0.5**: збалансовані відповіді з певною креативністю, добре підходять для загальних завдань розробки
- **0.6-1.0**: більш креативні та різноманітні відповіді, корисні для мозкового штурму та дослідження

```json title="aigcfroge.json"
{
  "agent": {
    "analyze": {
      "temperature": 0.1,
      "prompt": "{file:./prompts/analysis.txt}"
    },
    "build": {
      "temperature": 0.3
    },
    "brainstorm": {
      "temperature": 0.7,
      "prompt": "{file:./prompts/creative.txt}"
    }
  }
}
```

Якщо температуру не вказано, Aigcfroge використовує значення за замовчуванням, специфічні для моделі; зазвичай 0 для більшості моделей і 0.55 для моделей Qwen.

---

### Максимальна кількість кроків

Керуйте максимальною кількістю агентних ітерацій, які агент може виконати, перш ніж його змусять відповідати лише текстом. Це дає змогу користувачам, які хочуть контролювати витрати, встановити ліміт на агентні дії.

Якщо це не встановлено, агент продовжуватиме ітерувати, доки модель не вирішить зупинитися або користувач не перерве сесію.

```json title="aigcfroge.json"
{
  "agent": {
    "quick-thinker": {
      "description": "Fast reasoning with limited iterations",
      "prompt": "You are a quick thinker. Solve problems with minimal steps.",
      "steps": 5
    }
  }
}
```

Коли ліміт досягнуто, агент отримує спеціальний системний промпт, який інструктує його відповісти узагальненням своєї роботи та рекомендованими завданнями, що лишилися.

:::caution
Застаріле поле `maxSteps` більше не використовується. Натомість використовуйте `steps`.
:::

---

### Вимкнення

Встановіть `true`, щоб вимкнути агента.

```json title="aigcfroge.json"
{
  "agent": {
    "review": {
      "disable": true
    }
  }
}
```

---

### Промпт

Вкажіть власний файл системного промпту для цього агента за допомогою конфігурації `prompt`. Файл промпту має містити інструкції, специфічні для призначення агента.

```json title="aigcfroge.json"
{
  "agent": {
    "review": {
      "prompt": "{file:./prompts/code-review.txt}"
    }
  }
}
```

Цей шлях є відносним до місця розташування файлу конфігурації. Тож він працює як для глобальної конфігурації Aigcfroge, так і для конфігурації, специфічної для проєкту.

---

### Модель

Використовуйте конфігурацію `model`, щоб замінити модель для цього агента. Корисно для використання різних моделей, оптимізованих для різних завдань. Наприклад, швидша модель для планування, потужніша модель для реалізації.

:::tip
Якщо ви не вказуєте модель, основні агенти використовують [глобально налаштовану модель](/docs/config#models), тоді як субагенти використовуватимуть модель основного агента, який викликав субагента.
:::

```json title="aigcfroge.json"
{
  "agent": {
    "plan": {
      "model": "anthropic/claude-haiku-4-20250514"
    }
  }
}
```

Ідентифікатор моделі у вашій конфігурації Aigcfroge використовує формат `provider/model-id`. Наприклад, якщо ви використовуєте [Aigcfroge Zen](/docs/zen), ви вкажете `aigcfroge/gpt-5.1-codex` для GPT 5.1 Codex.

---

### Інструменти (застаріло)

`tools` — **застаріле** поле. Віддавайте перевагу полю [`permission`](#permissions) агента для нових конфігурацій, оновлень і детальнішого контролю.

Дає змогу контролювати, які інструменти доступні в цьому агенті. Ви можете вмикати або вимикати конкретні інструменти, встановлюючи їм значення `true` або `false`. У конфігурації `tools` агента `true` еквівалентний дозволу `{"*": "allow"}`, а `false` — дозволу `{"*": "deny"}`.

```json title="aigcfroge.json" {3-6,9-12}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "tools": {
    "write": true,
    "bash": true
  },
  "agent": {
    "plan": {
      "tools": {
        "write": false,
        "bash": false
      }
    }
  }
}
```

:::note
Конфігурація, специфічна для агента, замінює глобальну конфігурацію.
:::

Ви також можете використовувати підстановочні символи в застарілих записах `tools`, щоб керувати кількома інструментами одночасно. Наприклад, щоб вимкнути всі інструменти з MCP-сервера:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "agent": {
    "readonly": {
      "tools": {
        "mymcp_*": false,
        "write": false,
        "edit": false
      }
    }
  }
}
```

[Дізнайтеся більше про інструменти](/docs/tools).

### Дозволи

Ви можете налаштувати дозволи, щоб керувати діями, які агент може виконувати. Кожен ключ дозволу може бути встановлений на:

- `"ask"` — питати підтвердження перед запуском інструмента
- `"allow"` — дозволити всі операції без підтвердження
- `"deny"` — вимкнути інструмент

Доступні ключі дозволів:

| Ключ                | Інструменти, які він контролює                                  |
| -------------------- | ---------------------------------------------------------------- |
| `read`               | `read`                                                           |
| `edit`               | `write`, `edit`, `apply_patch`                                   |
| `glob`               | `glob`                                                           |
| `grep`               | `grep`                                                           |
| `list`               | `list`                                                           |
| `bash`               | `bash`                                                           |
| `task`               | `task`                                                           |
| `external_directory` | Будь-який інструмент, який читає або записує файли поза робочим деревом проєкту |
| `todowrite`          | `todowrite`, `todoread`                                          |
| `webfetch`           | `webfetch`                                                       |
| `websearch`          | `websearch`                                                      |
| `lsp`                | `lsp`                                                            |
| `skill`              | `skill`                                                          |
| `question`           | `question`                                                       |
| `doom_loop`          | Промпти відновлення, коли здається, що агент застряг             |

`read`, `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`, `lsp` та `skill` приймають або скорочену дію (`"allow" | "ask" | "deny"`), або об'єкт зіставлення glob/шаблон → дія для детального контролю. Решта ключів приймають лише скорочену дію.

:::note
Ключі дозволів зіставляються як шаблони з підстановочними символами з базовою назвою інструмента, тож той самий синтаксис працює для вбудованих, власних та MCP-інструментів — наприклад, `"mymcp_*": "deny"` забороняє всі інструменти з MCP-сервера, а `"mymcp_search": "ask"` адресує лише один.
:::

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "edit": "deny"
  }
}
```

Ви можете замінити ці дозволи для кожного агента окремо.

```json title="aigcfroge.json" {3-5,8-10}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "edit": "deny"
  },
  "agent": {
    "build": {
      "permission": {
        "edit": "ask"
      }
    }
  }
}
```

Ви також можете встановлювати дозволи в Markdown-агентах.

```markdown title="~/.config/aigcfroge/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash:
    "*": ask
    "git diff": allow
    "git log*": allow
    "grep *": allow
  webfetch: deny
---

Only analyze code and suggest changes.
```

Ви можете встановлювати дозволи для конкретних bash-команд.

```json title="aigcfroge.json" {7}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git push": "ask",
          "grep *": "allow"
        }
      }
    }
  }
}
```

Тут можна використати glob-шаблон.

```json title="aigcfroge.json" {7}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "git *": "ask"
        }
      }
    }
  }
}
```

А ще ви можете використовувати підстановочний символ `*`, щоб керувати дозволами для всіх команд.
Оскільки останнє збігле правило має пріоритет, розміщуйте підстановочний символ `*` першим, а конкретні правила — після нього.

```json title="aigcfroge.json" {8}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git status *": "allow"
        }
      }
    }
  }
}
```

[Дізнайтеся більше про дозволи](/docs/permissions).

### Режим

Керуйте режимом агента за допомогою конфігурації `mode`. Опція `mode` використовується для визначення того, як можна використовувати агента.

```json title="aigcfroge.json"
{
  "agent": {
    "review": {
      "mode": "subagent"
    }
  }
}
```

Опція `mode` може бути встановлена на `primary`, `subagent` або `all`. Якщо `mode` не вказано, за замовчуванням встановлюється `all`.

---

### Прихований

Сховайте субагента з меню автодоповнення `@` за допомогою `hidden: true`. Корисно для внутрішніх субагентів, які інші агенти мають викликати лише програмно через інструмент Task.

```json title="aigcfroge.json"
{
  "agent": {
    "internal-helper": {
      "mode": "subagent",
      "hidden": true
    }
  }
}
```

Це впливає лише на видимість для користувача в меню автодоповнення. Прихованих агентів модель все ще може викликати через інструмент Task, якщо це дозволяють дозволи.

:::note
Застосовується лише до агентів із `mode: subagent`.
:::

---

### Дозволи Task

Керуйте тим, яких субагентів агент може викликати через інструмент Task, за допомогою `permission.task`. Використовує glob-шаблони для гнучкого зіставлення.

```json title="aigcfroge.json"
{
  "agent": {
    "orchestrator": {
      "mode": "primary",
      "permission": {
        "task": {
          "*": "deny",
          "orchestrator-*": "allow",
          "code-reviewer": "ask"
        }
      }
    }
  }
}
```

Коли встановлено `deny`, субагента повністю видаляють з опису інструмента Task, тож модель не намагатиметься його викликати.

:::tip
Правила оцінюються по порядку, і **виграє останнє збігле правило**. У прикладі вище `orchestrator-planner` збігається і з `*` (deny), і з `orchestrator-*` (allow), але оскільки `orchestrator-*` стоїть після `*`, результат — `allow`.
:::

:::tip
Користувачі завжди можуть викликати будь-якого субагента безпосередньо через меню автодоповнення `@`, навіть якщо дозволи Task агента це забороняли б.
:::

### Колір

Налаштуйте візуальний вигляд агента в інтерфейсі за допомогою опції `color`. Це впливає на те, як агент відображається в інтерфейсі.

Використовуйте коректний hex-колір (наприклад, `#FF5733`) або колір теми: `primary`, `secondary`, `accent`, `success`, `warning`, `error`, `info`.

```json title="aigcfroge.json"
{
  "agent": {
    "creative": {
      "color": "#ff6b6b"
    },
    "code-reviewer": {
      "color": "accent"
    }
  }
}
```

### Top P

Керуйте різноманітністю відповідей за допомогою опції `top_p`. Альтернатива температурі для керування випадковістю.

```json title="aigcfroge.json"
{
  "agent": {
    "brainstorm": {
      "top_p": 0.9
    }
  }
}
```

Значення коливаються від 0.0 до 1.0. Нижчі значення роблять відповіді більш зосередженими, вищі — більш різноманітними.

### Додаткові

Будь-які інші опції, які ви вказуєте в конфігурації агента, будуть **передані безпосередньо** провайдеру як опції моделі. Це дає змогу використовувати функції та параметри, специфічні для провайдера.

Наприклад, з моделями міркування OpenAI ви можете керувати рівнем міркування:

```json title="aigcfroge.json" {6,7}
{
  "agent": {
    "deep-thinker": {
      "description": "Agent that uses high reasoning effort for complex problems",
      "model": "openai/gpt-5",
      "reasoningEffort": "high",
      "textVerbosity": "low"
    }
  }
}
```

Ці додаткові опції є специфічними для моделі та провайдера. Перевірте документацію вашого провайдера щодо доступних параметрів.

:::tip
Запустіть `aigcfroge models`, щоб побачити список доступних моделей.
:::

## Створення агентів

Ви можете створювати нових агентів за допомогою такої команди:

```bash
aigcfroge agent create
```

Ця інтерактивна команда:

1. Запитає, куди зберегти агента: глобально чи для конкретного проєкту.
2. Опише, що має робити агент.
3. Згенерує відповідний системний промпт та ідентифікатор.
4. Дасть змогу вибрати, які дозволи матиме агент (усе, що ви не виберете, буде заборонено).
5. Нарешті, створить markdown-файл із конфігурацією агента.

## Сценарії використання

Ось кілька типових сценаріїв використання різних агентів.

- **Агент Build**: повноцінна робота над розробкою з усіма ввімкненими інструментами
- **Агент Plan**: аналіз і планування без внесення змін
- **Агент Review**: рев'ю коду з доступом лише для читання та інструментами документації
- **Агент Debug**: зосереджений на розслідуванні з увімкненими bash та інструментами читання
- **Агент Docs**: написання документації з операціями над файлами, але без системних команд
