title: Вирішення проблем
description: Поширені проблеми та способи їх вирішення.
---

Щоб налагодити проблеми з Aigcfroge, почніть із перевірки журналів і локальних даних, які він зберігає на диску.

---

## Журнали

Файли журналів записуються в:

- **macOS/Linux**: `~/.local/share/aigcfroge/log/`
- **Windows**: натисніть `WIN+R` і вставте `%USERPROFILE%\.local\share\aigcfroge\log`

Файли журналів іменуються з позначками часу (наприклад, `2025-01-09T123456.log`), і зберігаються останні 10 файлів журналів.

Рівень журналювання можна задати за допомогою опції командного рядка `--log-level`, щоб отримати детальнішу налагоджувальну інформацію. Наприклад, `aigcfroge --log-level DEBUG`.

---

## Сховище

aigcfroge зберігає дані сесій та інші дані застосунку на диску в:

- **macOS/Linux**: `~/.local/share/aigcfroge/`
- **Windows**: натисніть `WIN+R` і вставте `%USERPROFILE%\.local\share\aigcfroge`

Цей каталог містить:

- `auth.json` — дані автентифікації, як-от API-ключі, токени OAuth
- `log/` — журнали застосунку
- `project/` — дані, специфічні для проєкту, як-от дані сесій і повідомлень
  - Якщо проєкт перебуває в Git-репозиторії, дані зберігаються в `./<project-slug>/storage/`
  - Якщо це не Git-репозиторій, дані зберігаються в `./global/storage/`

---

## Видалення

Щоб видалити CLI Aigcfroge та пов'язані з ним файли, виконайте:

```bash
aigcfroge uninstall
```

Команда показує, що буде видалено, і запитує підтвердження. Перегляньте [довідку CLI](/docs/cli#uninstall), щоб дізнатися про параметри збереження вашої конфігурації чи даних застосунку.

Щоб видалити Aigcfroge Desktop, деінсталюйте застосунок за допомогою інструментів керування застосунками вашої операційної системи.

---

## Десктопний застосунок

Aigcfroge Desktop запускає локальний сервер Aigcfroge (супутній процес `aigcfroge-cli`) у фоновому режимі. Більшість проблем спричинені плагіном, що неправильно працює, пошкодженим кешем або неправильним налаштуванням сервера.

### Швидкі перевірки

- Повністю завершіть роботу застосунку та запустіть його знову.
- Якщо застосунок показує екран помилки, натисніть **Перезапустити** та скопіюйте деталі помилки.
- Лише macOS: меню `Aigcfroge` -> **Перезавантажити Webview** (допомагає, якщо інтерфейс порожній/завис).

---

### Вимкнення плагінів

Якщо десктопний застосунок аварійно завершується під час запуску, зависає або поводиться дивно, почніть із вимкнення плагінів.

#### Перевірте глобальну конфігурацію

Відкрийте файл глобальної конфігурації та знайдіть ключ `plugin`.

- **macOS/Linux**: `~/.config/aigcfroge/aigcfroge.jsonc` (або `~/.config/aigcfroge/aigcfroge.json`)
- **macOS/Linux** (старіші інсталяції): `~/.local/share/aigcfroge/aigcfroge.jsonc`
- **Windows**: натисніть `WIN+R` і вставте `%USERPROFILE%\.config\aigcfroge\aigcfroge.jsonc`

Якщо у вас налаштовані плагіни, тимчасово вимкніть їх, видаливши ключ або встановивши для нього порожній масив:

```jsonc
{
  "$schema": "https://aigcfroge.ai/config.json",
  "plugin": [],
}
```

#### Перевірте каталоги плагінів

Aigcfroge також може завантажувати локальні плагіни з диска. Тимчасово перемістіть їх (або перейменуйте каталог) і перезапустіть десктопний застосунок:

- **Глобальні плагіни**
  - **macOS/Linux**: `~/.config/aigcfroge/plugins/`
  - **Windows**: натисніть `WIN+R` і вставте `%USERPROFILE%\.config\aigcfroge\plugins`
- **Плагіни проєкту** (лише якщо ви використовуєте конфігурацію для окремого проєкту)
  - `<your-project>/.aigcfroge/plugins/`

Якщо застосунок знову почав працювати, вмикайте плагіни по одному, щоб знайти той, який спричиняє проблему.

---

### Очищення кеша

Якщо вимкнення плагінів не допомагає (або встановлення плагіна застрягло), очистіть кеш, щоб Aigcfroge міг перебудувати його.

1. Повністю завершіть роботу Aigcfroge Desktop.
2. Видаліть каталог кеша:

- **macOS**: Finder -> `Cmd+Shift+G` -> вставте `~/.cache/aigcfroge`
- **Linux**: видаліть `~/.cache/aigcfroge` (або виконайте `rm -rf ~/.cache/aigcfroge`)
- **Windows**: натисніть `WIN+R` і вставте `%USERPROFILE%\.cache\aigcfroge`

3. Перезапустіть Aigcfroge Desktop.

---

### Виправлення проблем із підключенням до сервера

Aigcfroge Desktop може або запускати власний локальний сервер (за замовчуванням), або підключатися до URL-адреси сервера, яку ви налаштували.

Якщо ви бачите діалогове вікно **«Не вдалося підключитися»** (або застосунок не проходить далі екрана завантаження), перевірте наявність спеціальної URL-адреси сервера.

#### Очищення URL-адреси сервера за замовчуванням у десктопі

На головному екрані натисніть назву сервера (зі статусною точкою), щоб відкрити вибір сервера. У розділі **Сервер за замовчуванням** натисніть **Очистити**.

#### Видаліть `server.port` / `server.hostname` зі своєї конфігурації

Якщо ваш `aigcfroge.json(c)` містить розділ `server`, тимчасово видаліть його та перезапустіть десктопний застосунок.

#### Перевірка змінних середовища

Якщо у вашому середовищі встановлено змінну `AIGCFROGE_PORT`, десктопний застосунок спробує використати цей порт для локального сервера.

- Скиньте `AIGCFROGE_PORT` (або оберіть вільний порт) і перезапустіть.

---

### Linux: проблеми з Wayland / X11

У Linux деякі конфігурації Wayland можуть спричиняти порожні вікна або помилки композитора.

- Якщо ви працюєте у Wayland і застосунок порожній/завершується аварійно, спробуйте запустити його з `OC_ALLOW_WAYLAND=1`.
- Якщо стало гірше, видаліть його та спробуйте запустити застосунок у сесії X11.

---

### Windows: середовище виконання WebView2

У Windows Aigcfroge Desktop потребує середовище виконання **WebView2** від Microsoft Edge. Якщо застосунок відкривається порожнім вікном або не запускається, встановіть/оновіть WebView2 і спробуйте знову.

---

### Windows: загальні проблеми з продуктивністю

Якщо ви стикаєтеся з повільною продуктивністю, проблемами доступу до файлів або проблемами термінала у Windows, спробуйте використати [WSL (підсистему Windows для Linux)](/docs/windows-wsl). WSL надає середовище Linux, яке безперебійніше працює з функціями Aigcfroge.

---

### Сповіщення не показуються

Aigcfroge Desktop показує системні сповіщення лише тоді, коли:

- сповіщення для Aigcfroge ввімкнені в налаштуваннях вашої ОС, і
- вікно застосунку не має фокусу.

---

### Скидання сховища десктопного застосунку (крайній засіб)

Якщо застосунок не запускається, і ви не можете очистити налаштування з інтерфейсу, скиньте збережений стан десктопного застосунку.

1. Завершіть роботу Aigcfroge Desktop.
2. Знайдіть і видаліть ці файли (вони містяться в каталозі даних застосунку Aigcfroge Desktop):

- `aigcfroge.settings.dat` (URL-адреса сервера за замовчуванням у десктопі)
- `aigcfroge.global.dat` і `aigcfroge.workspace.*.dat` (стан інтерфейсу, як-от останні сервери/проєкти)

Щоб швидко знайти каталог:

- **macOS**: Finder -> `Cmd+Shift+G` -> `~/Library/Application Support` (потім знайдіть файли, зазначені вище)
- **Linux**: знайдіть файли, зазначені вище, у `~/.local/share`
- **Windows**: натисніть `WIN+R` -> `%APPDATA%` (потім знайдіть файли, зазначені вище)

## Поширені проблеми

Ось деякі поширені проблеми та способи їх вирішення.

---

### Aigcfroge не запускається

1. Перевірте журнали на наявність повідомлень про помилки
2. Спробуйте запустити з `--print-logs`, щоб побачити вивід у терміналі
3. Переконайтеся, що у вас найновіша версія, за допомогою `aigcfroge upgrade`

---

### Проблеми з автентифікацією

1. Спробуйте повторно автентифікуватися за допомогою команди `/connect` у TUI
2. Перевірте, чи ваші API-ключі дійсні
3. Переконайтеся, що ваша мережа дозволяє підключення до API провайдера

---

### Модель недоступна

1. Перевірте, що ви автентифікувалися через провайдера
2. Переконайтеся, що назва моделі у вашій конфігурації правильна
3. Деякі моделі можуть вимагати спеціального доступу або підписок

Якщо ви стикаєтеся з `ProviderModelNotFoundError`, найімовірніше, ви десь
неправильно посилаєтеся на модель.
Моделі слід посилати так: `<providerId>/<modelId>`

Приклади:

- `openai/gpt-4.1`
- `openrouter/google/gemini-2.5-flash`
- `aigcfroge/kimi-k2`

Щоб дізнатися, до яких моделей у вас є доступ, виконайте `aigcfroge models`

---

### ProviderInitError

Якщо ви стикаєтеся з ProviderInitError, найімовірніше, у вас недійсна або пошкоджена конфігурація.

Щоб вирішити цю проблему:

1. Спочатку переконайтеся, що ваш провайдер налаштований правильно, дотримуючись [інструкції з провайдерів](/docs/providers)
2. Якщо проблема не зникає, спробуйте очистити збережену конфігурацію:

   ```bash
   rm -rf ~/.local/share/aigcfroge
   ```

   У Windows натисніть `WIN+R` і видаліть: `%USERPROFILE%\.local\share\aigcfroge`

3. Повторно автентифікуйтеся через свого провайдера за допомогою команди `/connect` у TUI.

---

### AI_APICallError та проблеми з пакетами провайдерів

Якщо ви стикаєтеся з помилками викликів API, це може бути пов'язано із застарілими пакетами провайдерів. aigcfroge динамічно встановлює пакети провайдерів (OpenAI, Anthropic, Google тощо) у міру потреби та кешує їх локально.

Щоб вирішити проблеми з пакетами провайдерів:

1. Очистіть кеш пакетів провайдерів:

   ```bash
   rm -rf ~/.cache/aigcfroge
   ```

   У Windows натисніть `WIN+R` і видаліть: `%USERPROFILE%\.cache\aigcfroge`

2. Перезапустіть aigcfroge, щоб переінсталювати найновіші пакети провайдерів

Це змусить aigcfroge завантажити найновіші версії пакетів провайдерів, що часто вирішує проблеми сумісності з параметрами моделей і змінами API.

---

### Копіювання/вставлення не працює в Linux

Користувачам Linux для роботи копіювання/вставлення потрібно встановити одну з таких утиліт для буфера обміну:

**Для систем X11:**

```bash
apt install -y xclip
# or
apt install -y xsel
```

**Для систем Wayland:**

```bash
apt install -y wl-clipboard
```

**Для безголовних середовищ:**

```bash
apt install -y xvfb
# and run:
Xvfb :99 -screen 0 1024x768x24 > /dev/null 2>&1 &
export DISPLAY=:99.0
```

aigcfroge визначить, чи ви використовуєте Wayland, і надасть перевагу `wl-clipboard`; інакше він спробує знайти інструменти буфера обміну в такому порядку: `xclip` та `xsel`.
