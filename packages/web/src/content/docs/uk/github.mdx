---
title: GitHub
description: Використовуйте Aigcfroge у issue та pull-requests GitHub.
---

Aigcfroge інтегрується з вашим робочим процесом GitHub. Згадайте `/aigcfroge` або `/oc` у своєму коментарі, і Aigcfroge виконає завдання у вашому раннері GitHub Actions.

---

## Можливості

- **Розбір issue**: Попросіть Aigcfroge розглянути issue та пояснити вам його.
- **Виправлення та реалізація**: Попросіть Aigcfroge виправити issue або реалізувати функцію. Він працюватиме в новій гілці та надішле PR з усіма змінами.
- **Безпека**: Aigcfroge працює всередині ваших раннерів GitHub.

---

## Встановлення

Виконайте наступну команду в проєкті, який знаходиться в репозиторії GitHub:

```bash
aigcfroge github install
```

Це проведе вас через встановлення застосунку GitHub, створення робочого процесу та налаштування секретів.

---

### Ручне налаштування

Або ви можете налаштувати його вручну.

1. **Встановіть застосунок GitHub**

   Перейдіть до [**github.com/apps/aigcfroge-agent**](https://github.com/apps/aigcfroge-agent). Переконайтеся, що він встановлений на цільовому репозиторії.

2. **Додайте робочий процес**

   Додайте наступний файл робочого процесу до `.github/workflows/aigcfroge.yml` у вашому репозиторії. Переконайтеся, що у `env` задано відповідну `model` та потрібні ключі API.

   ```yml title=".github/workflows/aigcfroge.yml" {24,26}
   name: aigcfroge

   on:
     issue_comment:
       types: [created]
     pull_request_review_comment:
       types: [created]

   jobs:
     aigcfroge:
       if: |
         contains(github.event.comment.body, '/oc') ||
         contains(github.event.comment.body, '/aigcfroge')
       runs-on: ubuntu-latest
       permissions:
         id-token: write
       steps:
          - name: Checkout repository
            uses: actions/checkout@v6
            with:
              fetch-depth: 1
              persist-credentials: false

          - name: Run Aigcfroge
           uses: keerzzz/AigcForge/github@latest
           env:
             ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
           with:
             model: anthropic/claude-sonnet-4-20250514
             # share: true
             # github_token: xxxx
   ```

3. **Збережіть ключі API в секретах**

   У **налаштуваннях** вашої організації або проєкту розгорніть **Secrets and variables** ліворуч і виберіть **Actions**. Потім додайте потрібні ключі API.

## Конфігурація

- `model`: Модель для використання з Aigcfroge. Приймає формат `provider/model`. Це поле **обов'язкове**.
- `agent`: Агент для використання. Має бути первинним агентом. Якщо не знайдено, повертається до `default_agent` із конфігурації або `"build"`.
- `share`: Чи ділитися сесією Aigcfroge. За замовчуванням — **true** для публічних репозиторіїв.
- `prompt`: Необов'язковий власний промпт для заміни поведінки за замовчуванням. Використовуйте його, щоб налаштувати, як Aigcfroge обробляє запити.
- `token`: Необов'язковий токен доступу GitHub для виконання операцій, таких як створення коментарів, коміт змін та відкриття pull requests. За замовчуванням Aigcfroge використовує токен доступу встановлення застосунку Aigcfroge GitHub, тому коміти, коментарі та pull requests виглядають як такі, що надходять від застосунку.

  Крім того, ви можете використати [вбудований `GITHUB_TOKEN`](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token) раннера GitHub Action, не встановлюючи застосунок Aigcfroge GitHub. Просто переконайтеся, що у вашому робочому процесі надано потрібні дозволи:

  ```yaml
  permissions:
    id-token: write
    contents: write
    pull-requests: write
    issues: write
  ```

  Ви також можете використати [персональний токен доступу](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)(PAT), якщо це зручніше.

## Підтримувані події

Aigcfroge можна запускати за допомогою наступних подій GitHub:

| Тип події                  | Що запускає                                     | Деталі                                                                                                                 |
| -------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `issue_comment`            | Коментар до issue або PR                        | Згадайте `/aigcfroge` або `/oc` у своєму коментарі. Aigcfroge читає контекст і може створювати гілки, відкривати PR або відповідати. |
| `pull_request_review_comment` | Коментар до конкретних рядків коду в PR      | Згадайте `/aigcfroge` або `/oc` під час рев'ю коду. Aigcfroge отримує шлях до файлу, номери рядків і контекст diff.     |
| `issues`                    | Issue відкрито або змінено                       | Автоматично запускайте Aigcfroge, коли issue створюються або змінюються. Потребує введення `prompt`.                    |
| `pull_request`              | PR відкрито або оновлено                         | Автоматично запускайте Aigcfroge, коли PR відкриваються, синхронізуються або перевідкриваються. Корисно для автоматизованих рев'ю. |
| `schedule`                  | Розклад на основі Cron                           | Запускайте Aigcfroge за розкладом. Потребує введення `prompt`. Вивід надходить до журналів і PR (немає issue для коментаря). |
| `workflow_dispatch`         | Ручний запуск з інтерфейсу GitHub                | Запускайте Aigcfroge за потреби через вкладку Actions. Потребує введення `prompt`. Вивід надходить до журналів і PR.   |

### Приклад розкладу

Запускайте Aigcfroge за розкладом для виконання автоматизованих завдань:

```yaml title=".github/workflows/aigcfroge-scheduled.yml"
name: Scheduled Aigcfroge Task

on:
  schedule:
    - cron: "0 9 * * 1" # Every Monday at 9am UTC

jobs:
  aigcfroge:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6
        with:
          persist-credentials: false

      - name: Run Aigcfroge
        uses: keerzzz/AigcForge/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review the codebase for any TODO comments and create a summary.
            If you find issues worth addressing, open an issue to track them.
```

Для запланованих подій введення `prompt` є **обов'язковим**, оскільки немає коментаря, з якого можна отримати інструкції. Заплановані робочі процеси працюють без контексту користувача для перевірки дозволів, тому робочий процес має надавати `contents: write` та `pull-requests: write`, якщо ви очікуєте, що Aigcfroge створюватиме гілки або PR.

### Приклад Pull Request

Автоматично перевіряйте PR, коли їх відкривають або оновлюють:

```yaml title=".github/workflows/aigcfroge-review.yml"
name: aigcfroge-review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

jobs:
  review:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
      pull-requests: read
      issues: read
    steps:
      - uses: actions/checkout@v6
        with:
          persist-credentials: false
      - uses: keerzzz/AigcForge/github@latest
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          use_github_token: true
          prompt: |
            Review this pull request:
            - Check for code quality issues
            - Look for potential bugs
            - Suggest improvements
```

Для подій `pull_request`, якщо `prompt` не надано, Aigcfroge за замовчуванням перевіряє pull request.

### Приклад розбору issue

Автоматично розбирайте нові issue. Цей приклад фільтрує облікові записи, старші за 30 днів, щоб зменшити спам:

```yaml title=".github/workflows/aigcfroge-triage.yml"
name: Issue Triage

on:
  issues:
    types: [opened]

jobs:
  triage:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: write
      pull-requests: write
      issues: write
    steps:
      - name: Check account age
        id: check
        uses: actions/github-script@v7
        with:
          script: |
            const user = await github.rest.users.getByUsername({
              username: context.payload.issue.user.login
            });
            const created = new Date(user.data.created_at);
            const days = (Date.now() - created) / (1000 * 60 * 60 * 24);
            return days >= 30;
          result-encoding: string

      - uses: actions/checkout@v6
        if: steps.check.outputs.result == 'true'
        with:
          persist-credentials: false

      - uses: keerzzz/AigcForge/github@latest
        if: steps.check.outputs.result == 'true'
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        with:
          model: anthropic/claude-sonnet-4-20250514
          prompt: |
            Review this issue. If there's a clear fix or relevant docs:
            - Provide documentation links
            - Add error handling guidance for code examples
            Otherwise, do not comment.
```

Для подій `issues` введення `prompt` є **обов'язковим**, оскільки немає коментаря, з якого можна отримати інструкції.

## Власні промпти

Замініть промпт за замовчуванням, щоб налаштувати поведінку Aigcfroge для вашого робочого процесу.

```yaml title=".github/workflows/aigcfroge.yml"
- uses: keerzzz/AigcForge/github@latest
  with:
    model: anthropic/claude-sonnet-4-5
    prompt: |
      Review this pull request:
      - Check for code quality issues
      - Look for potential bugs
      - Suggest improvements
```

Це корисно для застосування конкретних критеріїв рев'ю, стандартів кодування або фокусних областей, що стосуються вашого проєкту.

## Приклади

Ось кілька прикладів того, як можна використовувати Aigcfroge в GitHub.

- **Пояснити issue**

  Додайте цей коментар в issue GitHub.

  ```
  /aigcfroge explain this issue
  ```

  Aigcfroge прочитає весь тред, включно з усіма коментарями, і відповість зі зрозумілим поясненням.

- **Виправити issue**

  В issue GitHub напишіть:

  ```
  /aigcfroge fix this
  ```

  І Aigcfroge створить нову гілку, реалізує зміни та відкриє PR із цими змінами.

- **Перевіряти PR і вносити зміни**

  Залиште наступний коментар на PR GitHub.

  ```
  Delete the attachment from S3 when the note is removed /oc
  ```

  Aigcfroge реалізує запитувану зміну та закомітить її в той самий PR.

- **Перевіряти конкретні рядки коду**

  Залиште коментар безпосередньо на рядках коду у вкладці «Files» PR. Aigcfroge автоматично визначає файл, номери рядків і контекст diff, щоб надавати точні відповіді.

  ```
  [Comment on specific lines in Files tab]
  /oc add error handling here
  ```

  Коли ви коментуєте конкретні рядки, Aigcfroge отримує:
  - Точний файл, який перевіряється
  - Конкретні рядки коду
  - Оточуючий контекст diff
  - Інформацію про номери рядків

  Це дозволяє робити більш точні запити без необхідності вручну вказувати шляхи до файлів або номери рядків.
