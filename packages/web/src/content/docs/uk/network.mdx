Aigcfroge підтримує стандартні змінні середовища проксі та власні сертифікати для корпоративних мережевих середовищ.

---

## Проксі

Aigcfroge враховує стандартні змінні середовища проксі.

```bash
# HTTPS proxy (recommended)
export HTTPS_PROXY=https://proxy.example.com:8080

# HTTP proxy (if HTTPS not available)
export HTTP_PROXY=http://proxy.example.com:8080

# Bypass proxy for local server (required)
export NO_PROXY=localhost,127.0.0.1
```

:::caution
TUI спілкується з локальним HTTP-сервером. Для цього з'єднання ви маєте обійти проксі, щоб запобігти зацикленню маршрутизації.
:::

Ви можете налаштувати порт та ім'я хоста сервера за допомогою [прапорців CLI](/docs/cli#run).

---

### Автентифікація

Якщо ваш проксі потребує базової автентифікації, вкажіть облікові дані в URL.

```bash
export HTTPS_PROXY=http://username:password@proxy.example.com:8080
```

:::caution
Не зашивайте паролі в код. Використовуйте змінні середовища або безпечне сховище облікових даних.
:::

Для проксі, що потребують розширеної автентифікації, як-от NTLM або Kerberos, розгляньте використання LLM-шлюзу, який підтримує ваш метод автентифікації.

---

## Власні сертифікати

Якщо ваша компанія використовує власні центри сертифікації (CA) для HTTPS-з'єднань, налаштуйте Aigcfroge, щоб він їм довіряв.

```bash
export NODE_EXTRA_CA_CERTS=/path/to/ca-cert.pem
```

Це працює як для з'єднань через проксі, так і для прямого доступу до API.
