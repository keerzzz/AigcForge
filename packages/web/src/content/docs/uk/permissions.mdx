---
title: Дозволи
description: Контролюйте, які дії вимагають схвалення для виконання.
---

Aigcfroge використовує конфігурацію `permission`, щоб вирішувати, чи має певна дія виконуватися автоматично, чи потребує підтвердження від вас, чи має бути заблокована.

Починаючи з `v1.1.1`, застаріла булева конфігурація `tools` визнана застарілою й об'єднана з `permission`. Стара конфігурація `tools` досі підтримується для зворотної сумісності.

---

## Дії

Кожне правило дозволу зводиться до одного з варіантів:

- `"allow"` — виконати без схвалення
- `"ask"` — запитати схвалення
- `"deny"` — заблокувати дію

---

## Конфігурація

Ви можете встановлювати дозволи глобально (за допомогою `*`) і перевизначати конкретні інструменти.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "*": "ask",
    "bash": "allow",
    "edit": "deny"
  }
}
```

Ви також можете встановити всі дозволи одразу:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": "allow"
}
```

## Детальні правила (синтаксис об'єкта)

Для більшості дозволів ви можете використовувати об'єкт, щоб застосовувати різні дії залежно від вхідних даних інструмента.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "npm *": "allow",
      "rm *": "deny",
      "grep *": "allow"
    },
    "edit": {
      "*": "deny",
      "packages/web/src/content/docs/*.mdx": "allow"
    }
  }
}
```

Правила оцінюються за зіставленням із шаблоном, причому **виграє останнє збігле правило**. Поширений патерн — розміщувати загальне правило `"*"` першим, а конкретніші правила після нього.

### Підстановочні символи

Шаблони дозволів використовують просте зіставлення з підстановочними символами:

- `*` збігається з нулем або більше будь-яких символів
- `?` збігається рівно з одним символом
- Усі інші символи збігаються буквально

### Розгортання домашнього каталогу

Ви можете використовувати `~` або `$HOME` на початку шаблону, щоб посилатися на ваш домашній каталог. Це особливо корисно для правил [`external_directory`](#external-directories).

- `~/projects/*` -> `/Users/username/projects/*`
- `$HOME/projects/*` -> `/Users/username/projects/*`
- `~` -> `/Users/username`

### Зовнішні каталоги

Використовуйте `external_directory`, щоб дозволити виклики інструментів, які стосуються шляхів поза робочим каталогом, де було запущено Aigcfroge. Це стосується будь-якого інструмента, який приймає шлях як вхідні дані (наприклад, `read`, `edit`, `glob`, `grep` та багато команд `bash`).

Розгортання домашнього каталогу (наприклад, `~/...`) впливає лише на те, як записано шаблон. Воно не робить зовнішній шлях частиною поточного робочого простору, тож шляхи поза робочим каталогом все одно мають бути дозволені через `external_directory`.

Наприклад, це надає доступ до всього в `~/projects/personal/`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    }
  }
}
```

Будь-який каталог, дозволений тут, успадковує ті самі значення за замовчуванням, що й поточний робочий простір. Оскільки [`read` за замовчуванням дорівнює `allow`](#defaults), читання також дозволено для записів у `external_directory`, якщо їх не перевизначено. Додавайте явні правила, коли інструмент має бути обмежений у цих шляхах, наприклад блокуючи редагування, але зберігаючи читання:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "external_directory": {
      "~/projects/personal/**": "allow"
    },
    "edit": {
      "~/projects/personal/**": "deny"
    }
  }
}
```

Тримайте список зосередженим на довірених шляхах і додавайте додаткові правила дозволу чи заборони за потреби для інших інструментів (наприклад, `bash`).

## Доступні дозволи

Дозволи Aigcfroge ключуються за назвою інструмента, плюс кілька запобіжників:

- `read` — читання файлу (збігається зі шляхом файлу)
- `edit` — усі зміни файлів (охоплює `edit`, `write`, `patch`)
- `glob` — пошук файлів за шаблоном (збігається з glob-шаблоном)
- `grep` — пошук у вмісті (збігається з шаблоном регулярного виразу)
- `bash` — виконання команд оболонки (збігається з розібраними командами, як-от `git status --porcelain`)
- `task` — запуск підагентів (збігається з типом підагента)
- `skill` — завантаження навички (збігається з назвою навички)
- `lsp` — виконання запитів LSP (наразі не деталізований)
- `question` — запитування користувача під час виконання
- `webfetch` — отримання URL (збігається з URL)
- `websearch` — веб-пошук (збігається із запитом)
- `external_directory` — спрацьовує, коли інструмент стосується шляхів поза робочим каталогом проєкту
- `doom_loop` — спрацьовує, коли один і той самий виклик інструмента повторюється 3 рази з однаковими вхідними даними

## Значення за замовчуванням

Якщо ви нічого не вказуєте, Aigcfroge починає з дозвільних значень за замовчуванням:

- Більшість дозволів за замовчуванням мають значення `"allow"`.
- `doom_loop` та `external_directory` за замовчуванням мають значення `"ask"`.
- `read` має значення `"allow"`, але файли `.env` заборонені за замовчуванням:

```json title="aigcfroge.json"
{
  "permission": {
    "read": {
      "*": "allow",
      "*.env": "deny",
      "*.env.*": "deny",
      "*.env.example": "allow"
    }
  }
}
```

---

## Що робить "Ask"

Коли Aigcfroge запитує схвалення, інтерфейс пропонує три результати:

- `once` — схвалити лише цей запит
- `always` — схвалювати майбутні запити, що збігаються із запропонованими шаблонами (до кінця поточної сесії Aigcfroge)
- `reject` — відхилити запит

Набір шаблонів, які `always` схвалюватиме, надається інструментом (наприклад, схвалення bash зазвичай додають у білий список безпечний префікс команди, як-от `git status*`).

## Агенти

Ви можете перевизначати дозволи для кожного агента. Дозволи агентів об'єднуються з глобальною конфігурацією, і правила агентів мають пріоритет. [Дізнатися більше](/docs/agents#permissions) про дозволи агентів.

:::note
Зверніться до розділу [Детальні правила (синтаксис об'єкта)](#granular-rules-object-syntax) вище для детальніших прикладів зіставлення шаблонів.
:::

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "permission": {
    "bash": {
      "*": "ask",
      "git *": "allow",
      "git commit *": "deny",
      "git push *": "deny",
      "grep *": "allow"
    }
  },
  "agent": {
    "build": {
      "permission": {
        "bash": {
          "*": "ask",
          "git *": "allow",
          "git commit *": "ask",
          "git push *": "deny",
          "grep *": "allow"
        }
      }
    }
  }
}
```

Ви також можете налаштовувати дозволи агентів у Markdown:

```markdown title="~/.config/aigcfroge/agents/review.md"
---
description: Code review without edits
mode: subagent
permission:
  edit: deny
  bash: ask
  webfetch: deny
---

Only analyze code and suggest changes.
```

:::tip
Використовуйте зіставлення шаблонів для команд з аргументами. `"grep *"` дозволяє `grep pattern file.txt`, тоді як сам по собі `"grep"` заблокує її. Такі команди, як `git status`, працюють для поведінки за замовчуванням, але вимагають явного дозволу (наприклад, `"git status *"`), коли передаються аргументи.
:::
