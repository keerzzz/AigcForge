---
title: Політики
description: Контролюйте, які налаштовані ресурси може використовувати Aigcfroge.
---

Політики визначають, чи може Aigcfroge виконувати дію над іменованим ресурсом. Ця функція експериментальна й налаштовується через масив `experimental.policies` у файлі `aigcfroge.json`.

Політики відрізняються від [дозволів](/docs/permissions). Дозволи контролюють, що інструменти можуть робити під час сесії, тоді як політики визначають, чи може Aigcfroge використовувати такий ресурс, як провайдер LLM.

---

## Конфігурація

Кожне правило політики містить три поля:

- `effect` — або `"allow"`, або `"deny"`.
- `action` — операція, яку контролюють.
- `resource` — ідентифікатор ресурсу або шаблон із підстановочними символами, до яких застосовується правило.

Наприклад, забороніть використання провайдера `openai`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "openai"
      }
    ]
  }
}
```

Провайдер, заборонений політикою, недоступний для вибору або використання моделей, навіть якщо він має облікові дані чи налаштований правильним чином.

---

## Доступні політики

Aigcfroge наразі підтримує одну дію політики:

| Дія            | Ресурс                           | Опис                                          |
| -------------- | -------------------------------- | --------------------------------------------- |
| `provider.use` | Ідентифікатор провайдера, наприклад `openai` | Дозволити або заборонити використання LLM-провайдера. |

Більше дій політики може бути додано в майбутньому.

---

## Зіставлення

Поле `resource` підтримує зіставлення з підстановочними символами. Використовуйте `*` для збігу з нулем або більше символів і `?` для збігу з одним символом.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "company-*"
      }
    ]
  }
}
```

Це забороняє такі провайдери, як `company-us` та `company-eu`.

---

## Порядок правил

Коли збігається кілька правил, виграє останнє збігле правило. Спочатку розміщуйте широкі правила, а після них — конкретніші винятки.

Наприклад, дозвольте лише Anthropic:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "experimental": {
    "policies": [
      {
        "effect": "deny",
        "action": "provider.use",
        "resource": "*"
      },
      {
        "effect": "allow",
        "action": "provider.use",
        "resource": "anthropic"
      }
    ]
  }
}
```

Якщо жодна політика не збігається з провайдером, використання провайдера дозволено за замовчуванням.

Політики можна встановлювати як у глобальній конфігурації, так і в конфігурації проєкту. Якщо політики з обох місць збігаються з тим самим провайдером, глобальна політика має пріоритет над політикою проєкту. Це запобігає повторному ввімкненню репозиторієм провайдера, який ви забороняєте глобально.

---

## Списки провайдерів

Використовуйте політики замість застарілих налаштувань `disabled_providers` та `enabled_providers` під час керування доступом до провайдерів.

Щоб замінити `disabled_providers`:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "openai" },
      { "effect": "deny", "action": "provider.use", "resource": "google" }
    ]
  }
}
```

Щоб замінити `enabled_providers`, спочатку забороніть усі провайдери, а після цього дозвольте обрані:

```json title="aigcfroge.json"
{
  "experimental": {
    "policies": [
      { "effect": "deny", "action": "provider.use", "resource": "*" },
      { "effect": "allow", "action": "provider.use", "resource": "anthropic" },
      { "effect": "allow", "action": "provider.use", "resource": "openai" }
    ]
  }
}
```
