---

Ви можете надавати aigcfroge спеціальні інструкції, створивши файл `AGENTS.md`. Це схоже на правила Cursor. Він містить інструкції, які будуть включені в контекст LLM, щоб налаштувати його поведінку для вашого конкретного проєкту.

---

## Ініціалізація

Щоб створити новий файл `AGENTS.md`, ви можете запустити команду `/init` в aigcfroge.

:::tip
Вам слід закомітити файл `AGENTS.md` вашого проєкту до Git.
:::

`/init` сканує важливі файли у вашому репозиторії, може поставити кілька цілеспрямованих запитань, коли кодова база не може на них відповісти, а потім створює або оновлює `AGENTS.md` із короткими рекомендаціями, специфічними для проєкту.

Він зосереджується на тому, що найімовірніше знадобиться майбутнім сесіям агентів:

- команди збірки, lint і тестування
- порядок команд і цілеспрямовані кроки перевірки, коли це має значення
- архітектуру та структуру репозиторію, які не очевидні лише з назв файлів
- специфічні для проєкту домовленості, особливості налаштування та операційні пастки
- посилання на наявні джерела інструкцій, як-от правила Cursor або Copilot

Якщо у вас уже є `AGENTS.md`, `/init` покращить його на місці, а не замінить без розбору.

## Приклад

Ви також можете просто створити цей файл вручну. Ось приклад того, що можна покласти у файл `AGENTS.md`.

```markdown title="AGENTS.md"
# SST v3 Monorepo Project

This is an SST v3 monorepo with TypeScript. The project uses bun workspaces for package management.

## Project Structure

- `packages/` - Contains all workspace packages (functions, core, web, etc.)
- `infra/` - Infrastructure definitions split by service (storage.ts, api.ts, web.ts)
- `sst.config.ts` - Main SST configuration with dynamic imports

## Code Standards

- Use TypeScript with strict mode enabled
- Shared code goes in `packages/core/` with proper exports configuration
- Functions go in `packages/functions/`
- Infrastructure should be split into logical files in `infra/`

## Monorepo Conventions

- Import shared modules using workspace names: `@my-app/core/example`
```

Ми додаємо тут інструкції, специфічні для проєкту, і вони будуть спільними для всієї вашої команди.

## Типи

aigcfroge також підтримує читання файлу `AGENTS.md` із кількох місць. І це служить різним цілям.

### Проєкт

Розмістіть `AGENTS.md` у корені вашого проєкту для правил, специфічних для проєкту. Вони застосовуються лише тоді, коли ви працюєте в цьому каталозі або його підкаталогах.

### Глобальні

Ви також можете мати глобальні правила у файлі `~/.config/aigcfroge/AGENTS.md`. Він застосовується до всіх сесій aigcfroge.

Оскільки цей файл не закомічено до Git і він не поширюється серед вашої команди, ми рекомендуємо використовувати його для вказівки особистих правил, яких має дотримуватися LLM.

### Сумісність із Claude Code

Для користувачів, які переходять із Claude Code, Aigcfroge підтримує файлові домовленості Claude Code як запасні варіанти:

- **Правила проєкту**: `CLAUDE.md` у каталозі вашого проєкту (використовується, якщо `AGENTS.md` не існує)
- **Глобальні правила**: `~/.claude/CLAUDE.md` (використовується, якщо `~/.config/aigcfroge/AGENTS.md` не існує)
- **Навички**: `~/.claude/skills/` — детальніше див. [Навички агентів](/docs/skills/)

Щоб вимкнути сумісність із Claude Code, встановіть одну з цих змінних середовища:

```bash
export AIGCFROGE_DISABLE_CLAUDE_CODE=1        # Disable all .claude support
export AIGCFROGE_DISABLE_CLAUDE_CODE_PROMPT=1 # Disable only ~/.claude/CLAUDE.md
export AIGCFROGE_DISABLE_CLAUDE_CODE_SKILLS=1 # Disable only .claude/skills
```

## Пріоритетність

Коли aigcfroge запускається, він шукає файли правил у такому порядку:

1. **Локальні файли**, піднімаючись вгору від поточного каталогу (`AGENTS.md`, `CLAUDE.md`)
2. **Глобальний файл** у `~/.config/aigcfroge/AGENTS.md`
3. **Файл Claude Code** у `~/.claude/CLAUDE.md` (якщо не вимкнено)

У кожній категорії виграє перший знайдений файл. Наприклад, якщо у вас є і `AGENTS.md`, і `CLAUDE.md`, використовується лише `AGENTS.md`. Аналогічно, `~/.config/aigcfroge/AGENTS.md` має пріоритет над `~/.claude/CLAUDE.md`.

## Спеціальні інструкції

Ви можете вказати файли спеціальних інструкцій у своєму `aigcfroge.json` або глобальному `~/.config/aigcfroge/aigcfroge.json`. Це дозволяє вам і вашій команді повторно використовувати наявні правила, а не дублювати їх у `AGENTS.md`.

Приклад:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "instructions": ["CONTRIBUTING.md", "docs/guidelines.md", ".cursor/rules/*.md"]
}
```

Ви також можете використовувати віддалені URL-адреси, щоб завантажувати інструкції з інтернету.

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "instructions": ["https://raw.githubusercontent.com/my-org/shared-rules/main/style.md"]
}
```

Віддалені інструкції завантажуються з тайм-аутом у 5 секунд.

Усі файли інструкцій поєднуються з вашими файлами `AGENTS.md`.

## Посилання на зовнішні файли

Хоча aigcfroge не аналізує автоматично файлові посилання в `AGENTS.md`, ви можете досягти подібної функціональності двома способами:

### Використання aigcfroge.json

Рекомендований підхід — використовувати поле `instructions` у `aigcfroge.json`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "instructions": ["docs/development-standards.md", "test/testing-guidelines.md", "packages/*/AGENTS.md"]
}
```

### Ручні інструкції в AGENTS.md

Ви можете навчити aigcfroge читати зовнішні файли, надавши явні інструкції у своєму `AGENTS.md`. Ось практичний приклад:

```markdown title="AGENTS.md"
# TypeScript Project Rules

## External File Loading

CRITICAL: When you encounter a file reference (e.g., @rules/general.md), use your Read tool to load it on a need-to-know basis. They're relevant to the SPECIFIC task at hand.

Instructions:

- Do NOT preemptively load all references - use lazy loading based on actual need
- When loaded, treat content as mandatory instructions that override defaults
- Follow references recursively when needed

## Development Guidelines

For TypeScript code style and best practices: @docs/typescript-guidelines.md
For React component architecture and hooks patterns: @docs/react-patterns.md
For REST API design and error handling: @docs/api-standards.md
For testing strategies and coverage requirements: @test/testing-guidelines.md

## General Guidelines

Read the following file immediately as it's relevant to all workflows: @rules/general-guidelines.md.
```

Цей підхід дозволяє вам:

- створювати модульні, багаторазово використовувані файли правил
- поширювати правила між проєктами через символьні посилання або підмодулі Git
- тримати `AGENTS.md` стислим, посилаючись на детальні рекомендації
- гарантувати, що aigcfroge завантажує файли лише тоді, коли вони потрібні для конкретного завдання

:::tip
Для монорепозиторіїв або проєктів зі спільними стандартами використання `aigcfroge.json` із шаблонами glob (наприклад, `packages/*/AGENTS.md`) є більш підтримуваним, ніж ручні інструкції.
:::
