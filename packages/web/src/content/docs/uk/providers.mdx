Aigcfroge використовує [AI SDK](https://ai-sdk.dev/) та [Models.dev](https://models.dev) для підтримки **понад 75 LLM-провайдерів**, а також підтримує запуск локальних моделей.

Щоб додати провайдера, потрібно:

1. Додати API-ключі провайдера за допомогою команди `/connect`.
2. Налаштувати провайдера у вашій конфігурації Aigcfroge.

---

### Облікові дані

Коли ви додаєте API-ключі провайдера за допомогою команди `/connect`, вони зберігаються
у `~/.local/share/aigcfroge/auth.json`.

---

### Конфігурація

Ви можете налаштувати провайдерів через секцію `provider` у вашій
конфігурації Aigcfroge.

---

#### Базовий URL

Ви можете налаштувати базовий URL для будь-якого провайдера, задавши параметр `baseURL`. Це корисно під час використання проксі-сервісів або власних кінцевих точок.

```json title="aigcfroge.json" {6}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

## Aigcfroge Zen

Aigcfroge Zen — це список моделей, наданий командою Aigcfroge, які були
протестовані та перевірені на сумісність з Aigcfroge. [Докладніше](/docs/zen).

:::tip
Якщо ви новачок, рекомендуємо почати з Aigcfroge Zen.
:::

1. Виконайте команду `/connect` у TUI, виберіть `Aigcfroge Zen` і перейдіть на [aigcfroge.ai/auth](https://aigcfroge.ai/zen).

   ```txt
   /connect
   ```

2. Увійдіть, додайте свої платіжні дані та скопіюйте свій API-ключ.

3. Вставте свій API-ключ.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Виконайте `/models` у TUI, щоб побачити список моделей, які ми рекомендуємо.

   ```txt
   /models
   ```

Він працює як будь-який інший провайдер у Aigcfroge, і користуватися ним зовсім необов'язково.

### Amazon Bedrock

Щоб використовувати Amazon Bedrock з Aigcfroge:

1. Перейдіть до **каталогу моделей** у консолі Amazon Bedrock і надішліть запит
   на доступ до потрібних моделей.

   :::tip
   Ви повинні мати доступ до потрібної моделі в Amazon Bedrock.
   :::

2. **Налаштуйте автентифікацію** одним із наступних способів:

   ***

   #### Змінні середовища (швидкий старт)

   Задайте одну з цих змінних середовища під час запуску aigcfroge:

   ```bash
   # Option 1: Using AWS access keys
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY aigcfroge

   # Option 2: Using named AWS profile
   AWS_PROFILE=my-profile aigcfroge

   # Option 3: Using Bedrock bearer token
   AWS_BEARER_TOKEN_BEDROCK=XXX aigcfroge
   ```

   Або додайте їх до свого профілю bash:

   ```bash title="~/.bash_profile"
   export AWS_PROFILE=my-dev-profile
   export AWS_REGION=us-east-1
   ```

   ***

   #### Файл конфігурації (рекомендовано)

   Для конфігурації, специфічної для проєкту, або постійної конфігурації використовуйте `aigcfroge.json`:

   ```json title="aigcfroge.json"
   {
     "$schema": "https://aigcfroge.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "my-aws-profile"
         }
       }
     }
   }
   ```

   **Доступні параметри:**
   - `region` — регіон AWS (наприклад, `us-east-1`, `eu-west-1`)
   - `profile` — іменований профіль AWS із `~/.aws/credentials`
   - `endpoint` — власна URL-адреса кінцевої точки для VPC-кінцевих точок (псевдонім для загального параметра `baseURL`)

   :::tip
   Параметри у файлі конфігурації мають пріоритет над змінними середовища.
   :::

   ***

   #### Розширено: VPC-кінцеві точки

   Якщо ви використовуєте VPC-кінцеві точки для Bedrock:

   ```json title="aigcfroge.json"
   {
     "$schema": "https://aigcfroge.ai/config.json",
     "provider": {
       "amazon-bedrock": {
         "options": {
           "region": "us-east-1",
           "profile": "production",
           "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
         }
       }
     }
   }
   ```

   :::note
   Параметр `endpoint` є псевдонімом для загального параметра `baseURL` і використовує термінологію, специфічну для AWS. Якщо вказані обидва параметри `endpoint` та `baseURL`, пріоритет має `endpoint`.
   :::

   ***

   #### Методи автентифікації
   - **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: Створіть користувача IAM і згенеруйте ключі доступу в консолі AWS
   - **`AWS_PROFILE`**: Використовуйте іменовані профілі з `~/.aws/credentials`. Спочатку налаштуйте за допомогою `aws configure --profile my-profile` або `aws sso login`
   - **`AWS_BEARER_TOKEN_BEDROCK`**: Створіть довгострокові API-ключі в консолі Amazon Bedrock
   - **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: Для EKS IRSA (IAM Roles for Service Accounts) або інших середовищ Kubernetes із федерацією OIDC. Ці змінні середовища автоматично додаються Kubernetes під час використання анотацій сервісного облікового запису.

   ***

   #### Пріоритет автентифікації

   Amazon Bedrock використовує такий порядок пріоритету автентифікації:
   1. **Bearer-токен** — змінна середовища `AWS_BEARER_TOKEN_BEDROCK` або токен із команди `/connect`
   2. **Ланцюг облікових даних AWS** — профіль, ключі доступу, спільні облікові дані, ролі IAM, токени Web Identity (EKS IRSA), метадані екземпляра

   :::note
   Коли задано bearer-токен (через `/connect` або `AWS_BEARER_TOKEN_BEDROCK`), він має пріоритет над усіма методами облікових даних AWS, включно з налаштованими профілями.
   :::

3. Виконайте команду `/models`, щоб вибрати потрібну модель.

   ```txt
   /models
   ```

:::note
Для власних інференс-профілів використовуйте назву моделі та провайдера в ключі та задайте властивості `id` значення arn. Це забезпечує правильне кешування.
:::

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

Ви можете налаштувати aigcfroge для використання локальних моделей через [Atomic Chat](https://atomic.chat), настільний застосунок, який запускає локальні LLM за сумісним з OpenAI API-сервером (кінцева точка за замовчуванням `http://127.0.0.1:1337/v1`).

```json title="aigcfroge.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (local)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

У цьому прикладі:

- `atomic-chat` — це власний ID провайдера. Це може бути будь-який рядок.
- `npm` визначає пакет для використання цим провайдером. Тут `@ai-sdk/openai-compatible` використовується для будь-якого сумісного з OpenAI API.
- `name` — це відображувана назва провайдера в інтерфейсі.
- `options.baseURL` — це кінцева точка локального сервера. Змініть хост і порт відповідно до вашого налаштування Atomic Chat.
- `models` — це зіставлення ID моделей з їхніми відображуваними назвами. Кожен ID має збігатися з `id`, який повертає `GET /v1/models` — виконайте `curl http://127.0.0.1:1337/v1/models`, щоб перелічити ID, завантажені в Atomic Chat.

:::tip
Якщо виклики інструментів працюють погано, виберіть завантажену модель із сильною підтримкою викликів інструментів (наприклад, варіант Qwen-Coder або DeepSeek-Coder).
:::

### Azure OpenAI

:::note
Якщо ви отримуєте помилки "I'm sorry, but I cannot assist with that request", спробуйте змінити фільтр вмісту з **DefaultV2** на **Default** у вашому ресурсі Azure.

2. Перейдіть до [Azure AI Foundry](https://ai.azure.com/) і розгорніть модель.

   :::note
   Назва розгортання має збігатися з назвою моделі, щоб aigcfroge працював належним чином.
   :::

3. Виконайте команду `/connect` і знайдіть **Azure**.

   ```txt
   /connect
   ```

4. Введіть свій API-ключ.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

5. Задайте назву вашого ресурсу як змінну середовища:

   ```bash
   AZURE_RESOURCE_NAME=XXX aigcfroge
   ```

   Або додайте її до свого профілю bash:

   ```bash title="~/.bash_profile"
   export AZURE_RESOURCE_NAME=XXX
   ```

6. Виконайте команду `/models`, щоб вибрати розгорнуту модель.


### Cloudflare AI Gateway

Cloudflare AI Gateway надає доступ до моделей OpenAI, Anthropic, Workers AI тощо через єдину кінцеву точку. Завдяки [Unified Billing](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) вам не потрібні окремі API-ключі для кожного провайдера.

1. Перейдіть до [панелі керування Cloudflare](https://dash.cloudflare.com/), перейдіть до **AI** > **AI Gateway** і створіть новий шлюз. Занотуйте свій **Account ID** та **Gateway ID**.

2. Виконайте команду `/connect` і знайдіть **Cloudflare AI Gateway**.

   ```txt
   /connect
   ```

3. Введіть свій **Account ID** за запитом.

   ```txt
   ┌ Enter your Cloudflare Account ID
   │
   │
   └ enter
   ```

4. Введіть свій **Gateway ID** за запитом.

   ```txt
   ┌ Enter your Cloudflare AI Gateway ID
   │
   │
   └ enter
   ```

5. Введіть свій **Cloudflare API-токен**.

   ```txt
   ┌ Gateway API token
   │
   │
   └ enter
   ```

6. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

   Ви також можете додавати моделі через свою конфігурацію aigcfroge.

   ```json title="aigcfroge.json"
   {
     "$schema": "https://aigcfroge.ai/config.json",
     "provider": {
       "cloudflare-ai-gateway": {
         "models": {
           "openai/gpt-4o": {},
           "anthropic/claude-sonnet-4": {}
         }
       }
     }
   }
   ```

   Крім того, ви можете задати змінні середовища замість використання `/connect`.

   ```bash title="~/.bash_profile"
   export CLOUDFLARE_ACCOUNT_ID=your-32-character-account-id
   export CLOUDFLARE_GATEWAY_ID=your-gateway-id
   export CLOUDFLARE_API_TOKEN=your-api-token
   ```

### DigitalOcean

[Рушій інференсу](https://docs.digitalocean.com/products/inference/) DigitalOcean надає доступ до відкритих моделей, як-от GPT-OSS, Llama, Qwen та DeepSeek, а також до власних [Inference Routers](https://docs.digitalocean.com/products/genai-platform/concepts/inference-routers/), які маршрутизують кожен запит до найдешевшої, найшвидшої або найбільш придатної моделі для завдання.

Aigcfroge підтримує два методи автентифікації:

- **OAuth (рекомендовано)** — Увійдіть у свій обліковий запис DigitalOcean; Aigcfroge використовує ваш DigitalOcean API-токен безпосередньо для інференсу та виявляє ваші Inference Routers.
- **Model Access Key** — Вставте наявний ключ із консолі DigitalOcean.

#### OAuth (рекомендовано)

1. Виконайте команду `/connect` і знайдіть **DigitalOcean**.

   ```txt
   /connect
   ```

2. Виберіть **Login with DigitalOcean**.

   ```txt
   ┌ Select auth method
   │
   │ Login with DigitalOcean
   │ Paste Model Access Key
   └
   ```

3. Ваш браузер відкриється для авторизації Aigcfroge. Увійдіть і підтвердіть.

   :::note
   Aigcfroge запитує OAuth-дозволи `genai:read` та `inference:query`. Ваш DigitalOcean API-токен використовується безпосередньо для інференсу — окремий Model Access Key не створюється.
   :::

   :::note
   Inference Routers з'являються у списку вибору моделі лише після OAuth. Ручне вставлення Model Access Key не виявляє роутери.
   :::

4. Виконайте команду `/models`. Ваші Inference Routers з'являться у форматі `router:` у списку вибору моделі.

   ```txt
   /models
   ```

5. Щоб підхопити щойно створені Inference Routers, повторно виконайте `/connect` і знову виберіть **DigitalOcean**.

#### Використання Model Access Key

Якщо ви віддаєте перевагу вставляти ключ безпосередньо:

1. Перейдіть на сторінку **Manage** у розділі Inference [консолі DigitalOcean](https://cloud.digitalocean.com/) і створіть новий ключ.

2. Виконайте команду `/connect`, виберіть **DigitalOcean**, а потім **Paste Model Access Key**.

   ```txt
   ┌ Enter your DigitalOcean Model Access Key
   │
   │
   └ enter
   ```

   :::note
   За такого методу Inference Routers не виявляються автоматично. Щоб показати їх у списку вибору моделі, увійдіть через OAuth.
   :::

3. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

#### Змінна середовища

Крім того, задайте свій Model Access Key як змінну середовища.

```bash frame="none"
export DIGITALOCEAN_ACCESS_TOKEN=your-model-access-key
```

#### Inference Routers

Inference Routers дають змогу визначити політику маршрутизації для кількох моделей — обираючи найдешевшу, найшвидшу або найбільш придатну модель для кожного запиту залежно від завдання. Після OAuth Aigcfroge показує кожен роутер як `router:<router-name>` у списку вибору моделі.

Вибір моделі роутера є повноцінною заміною будь-якої іншої моделі — Aigcfroge пересилає ваш запит, а DigitalOcean обирає базову модель на основі політики вашого роутера. Докладніше про [Inference Routers](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/)

##### OAuth для Self-Hosted екземплярів

Щоб OAuth працював для вашого самостійно розміщеного екземпляра, потрібно створити
новий застосунок (Settings → Applications) із
URL-адресою зворотного виклику `http://127.0.0.1:8080/callback` та такими обсягами:

- api (доступ до API від вашого імені)
- read_user (читання вашої особистої інформації)
- read_repository (надає доступ лише для читання до репозиторію)

Потім передайте ID застосунку як змінну середовища:

```bash
export GITLAB_OAUTH_CLIENT_ID=your_application_id_here
```

Більше документації на головній сторінці [aigcfroge-gitlab-auth](https://www.npmjs.com/package/aigcfroge-gitlab-auth).

##### Робочі моделі GitLab Duo Agent Platform (DAP)

Робочі моделі DAP надають альтернативний шлях виконання, який маршрутизує виклики інструментів
через Duo Workflow Service (DWS) від GitLab замість стандартного агентного чату.
Коли вибрано модель `duo-workflow-*`, Aigcfroge:

1. Виявляє доступні моделі у вашому просторі імен GitLab
2. Показує засіб вибору, якщо доступно кілька моделей
3. Кешує вибрану модель на диску для швидкого подальшого запуску
4. Маршрутизує запити на виконання інструментів через систему інструментів Aigcfroge з контролем дозволів

Доступні робочі моделі DAP дотримуються угоди про найменування `duo-workflow-*` і
динамічно виявляються з вашого екземпляра GitLab.

##### API-інструменти GitLab (необов'язково, але настійно рекомендується)

Щоб отримати доступ до інструментів GitLab (merge requests, issues, pipelines, CI/CD тощо):

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "plugin": ["aigcfroge-gitlab-plugin"]
}
```

Цей плагін надає комплексні можливості керування репозиторієм GitLab, зокрема рев'ю MR, відстеження issues, моніторинг конвеєрів тощо.

#### Необов'язкові конфігурації

Якщо ви бачите функцію або модель Helicone, яка не налаштовується автоматично через aigcfroge, ви завжди можете налаштувати її самостійно.

Ось [каталог моделей Helicone](https://helicone.ai/models), він знадобиться вам, щоб отримати ID моделей, які ви хочете додати.

```jsonc title="~/.config/aigcfroge/aigcfroge.jsonc"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Model ID (from Helicone's model directory page)
          "name": "GPT-4o", // Your own custom name for the model
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Власні заголовки

Helicone підтримує власні заголовки для таких функцій, як кешування, відстеження користувача та керування сесіями. Додайте їх у конфігурацію провайдера за допомогою `options.headers`:

```jsonc title="~/.config/aigcfroge/aigcfroge.jsonc"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "aigcfroge",
        },
      },
    },
  },
}
```

##### Відстеження сесій

Функція [Sessions](https://docs.helicone.ai/features/sessions) від Helicone дає змогу групувати пов'язані LLM-запити разом. Використовуйте плагін [aigcfroge-helicone-session](https://github.com/H2Shami/aigcfroge-helicone-session), щоб автоматично зберігати кожну розмову Aigcfroge як сесію в Helicone.

```bash
npm install -g aigcfroge-helicone-session
```

Додайте його до своєї конфігурації.

```json title="aigcfroge.json"
{
  "plugin": ["aigcfroge-helicone-session"]
}
```

Плагін додає заголовки `Helicone-Session-Id` та `Helicone-Session-Name` у ваші запити. На сторінці Sessions у Helicone ви побачите кожну розмову Aigcfroge як окрему сесію.

##### Поширені заголовки Helicone

| Header                     | Description                                                   |
| -------------------------- | ------------------------------------------------------------- |
| `Helicone-Cache-Enabled`   | Увімкнути кешування відповідей (`true`/`false`)               |
| `Helicone-User-Id`         | Відстежувати показники за користувачем                        |
| `Helicone-Property-[Name]` | Додавати власні властивості (наприклад, `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id`       | Пов'язувати запити з версіями промптів                        |

Усі доступні заголовки див. у [каталозі заголовків Helicone](https://docs.helicone.ai/helicone-headers/header-directory).

### Snowflake Cortex

[Snowflake Cortex](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api) надає вам доступ до передових моделей (Claude, OpenAI GPT-5 тощо) через сумісний з OpenAI API. Немає облікового запису Snowflake? [Зареєструйтеся для безкоштовної пробної версії](https://signup.snowflake.com/?utm_source=aigcfroge&utm_medium=docs&utm_campaign=cortex-provider).

Основний робочий процес aigcfroge — написання коду, редагування файлів і виконання команд — покладається на виклики інструментів. Це підтримують лише родини Claude та OpenAI у Snowflake Cortex. Тому провайдер обмежений цими родинами, щоб підтримувати основний робочий процес.

Aigcfroge підтримує два методи автентифікації:

- **Browser OAuth (рекомендовано)** — увійдіть через свій IdP/SSO; не потрібно керувати секретами, токени оновлюються автоматично.
- **Ручний bearer-токен** — вставте PAT або JWT із консолі Snowflake.

#### Browser OAuth (рекомендовано)

1. Виконайте команду `/connect` і знайдіть **Snowflake Cortex**.

   ```txt
   /connect
   ```

2. Виберіть **Login with Snowflake (External Browser)**.

   ```txt
   ┌ Select auth method
   │
   │ Login with Snowflake (External Browser)
   │ Paste PAT or bearer token manually
   └
   ```

3. Введіть свій [ідентифікатор облікового запису](https://docs.snowflake.com/en/user-guide/admin-account-identifier) за запитом, наприклад `myorg-myaccount` або `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake Account Identifier
   │
   │
   └ enter
   ```

4. За бажанням введіть роль Snowflake, щоб обмежити сесію (наприклад, `SYSADMIN`). Залиште порожнім, щоб використовувати роль за замовчуванням.

5. Завершіть вхід у браузері, який відкриється. Aigcfroge автоматично перехоплює OAuth-зворотний виклик і зберігає токен — копіювання/вставлення не потрібне.

6. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

:::note
Browser OAuth використовує вбудовану інтеграцію безпеки `SNOWFLAKE$LOCAL_APPLICATION` від Snowflake ([документація](https://docs.snowflake.com/en/user-guide/oauth-local-applications)), яка поступово впроваджується для всіх облікових записів. Щоб перевірити доступність у вашому обліковому записі:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

Якщо результат порожній, скористайтеся методом **ручного bearer-токена** нижче, доки інтеграція впроваджується у ваш обліковий запис.
:::

#### Ручний bearer-токен

Якщо ви віддаєте перевагу вставляти токен безпосередньо або якщо `SNOWFLAKE$LOCAL_APPLICATION` ще недоступний у вашому обліковому записі:

1. Створіть [токен програмного доступу (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) у своєму обліковому записі Snowflake.

2. Виконайте команду `/connect`, знайдіть **Snowflake Cortex** і виберіть **Paste PAT or bearer token manually**.

3. Введіть свій [ідентифікатор облікового запису](https://docs.snowflake.com/en/user-guide/admin-account-identifier) за запитом.

4. Вставте свій PAT.

5. Виконайте команду `/models`, щоб вибрати модель.

   ```txt
   /models
   ```

#### Змінна середовища

Для CI або середовищ без графічного інтерфейсу задайте PAT або JWT перед запуском aigcfroge:

```bash
export SNOWFLAKE_ACCOUNT=myorg-myaccount
export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` приймає лише PAT або JWT — процес Browser OAuth доступний лише через `/connect` і не може бути налаштований через змінну середовища. `SNOWFLAKE_CORTEX_PAT` досі підтримується для зворотної сумісності.
:::

Каталог моделей надається автоматично. Достатньо мінімального `aigcfroge.json`:

```json title="aigcfroge.json"
{
  "$schema": "https://aigcfroge.ai/config.json",
  "model": "snowflake-cortex/claude-sonnet-4-6",
  "small_model": "snowflake-cortex/claude-haiku-4-5"
}
```

### xAI

Є три способи автентифікації: передплата SuperGrok через OAuth у браузері, та сама передплата SuperGrok через процес із кодом пристрою без графічного інтерфейсу (для VPS / SSH / Docker) або API-ключ із оплатою за використання з консолі xAI.

#### Варіант A — SuperGrok OAuth (вхід у браузері)

1. Виконайте команду `/connect` і знайдіть **xAI**.

   ```txt
   /connect
   ```

2. Виберіть **xAI Grok OAuth (SuperGrok Subscription)**. Aigcfroge відкриває екран згоди xAI у вашому браузері та очікує зворотний виклик на `http://127.0.0.1:56121/callback`.

3. Виконайте команду `/models`, щоб вибрати модель Grok.

   ```txt
   /models
   ```

Aigcfroge автоматично оновлює OAuth-токен доступу. Підходить будь-який план Grok або X Premium, що включає доступ до Grok API; окремий `XAI_API_KEY` не потрібен.

#### Варіант B — код пристрою SuperGrok (без графічного інтерфейсу / віддалений сервер / VPS)

Використовуйте це, коли Aigcfroge працює там, де браузер не може отримати доступ до перенаправлення на loopback: на VPS, у віддаленому середовищі розробки через SSH, у Docker, у CI тощо. На хості, де працює Aigcfroge, порт зворотного виклику не відкривається — натомість xAI передає CLI короткий код, який ви вводите в браузері на будь-якому іншому пристрої (ноутбуці, телефоні, …).

1. Виконайте команду `/connect` на віддаленому хості та знайдіть **xAI**.

   ```txt
   /connect
   ```

2. Виберіть **xAI Grok OAuth (Headless / Remote / VPS)**. Aigcfroge виводить URL для перевірки та короткий код користувача.

   ```txt
   Open https://x.ai/device on any device and enter code: ABCD-1234
   ```

3. Відкрийте URL на пристрої з браузером (ноутбуці або телефоні), введіть код і підтвердіть екран згоди. Aigcfroge опитує кінцеву точку токена xAI і зберігає отримані OAuth-токени після вашого підтвердження. Оновлення токена працює так само, як у варіанті A.

#### Варіант C — API-ключ

1. Перейдіть до [консолі xAI](https://console.x.ai/), створіть обліковий запис і згенеруйте API-ключ.

2. Виконайте команду `/connect` і знайдіть **xAI**.

   ```txt
   /connect
   ```

3. Виберіть **Manually enter API Key** і вставте свій xAI API-ключ.

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

4. Виконайте команду `/models`, щоб вибрати модель, наприклад _Grok Beta_.

   ```txt
   /models
   ```

## Власний провайдер

Щоб додати будь-якого **сумісного з OpenAI** провайдера, якого немає в списку команди `/connect`:

:::tip
Ви можете використовувати будь-якого сумісного з OpenAI провайдера з aigcfroge. Більшість сучасних AI-провайдерів пропонують сумісні з OpenAI API.
:::

1. Виконайте команду `/connect` і прокрутіть униз до **Other**.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◆  Select provider
   │  ...
   │  ● Other
   └
   ```

2. Введіть унікальний ID для провайдера.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ◇  Enter provider id
   │  myprovider
   └
   ```

   :::note
   Оберіть запам'ятовуваний ID — ви використовуватимете його у файлі конфігурації.
   :::

3. Введіть свій API-ключ для провайдера.

   ```bash
   $ /connect

   ┌  Add credential
   │
   ▲  This only stores a credential for myprovider - you will need to configure it in aigcfroge.json, check the docs for examples.
   │
   ◇  Enter your API key
   │  sk-...
   └
   ```

4. Створіть або оновіть файл `aigcfroge.json` у каталозі вашого проєкту:

   ```json title="aigcfroge.json" ""myprovider"" {5-15}
   {
     "$schema": "https://aigcfroge.ai/config.json",
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "My AI ProviderDisplay Name",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "My Model Display Name"
           }
         }
       }
     }
   }
   ```

   Ось параметри конфігурації:
   - **npm**: пакет AI SDK для використання, `@ai-sdk/openai-compatible` для сумісних з OpenAI провайдерів (для `/v1/chat/completions`). Якщо ваш провайдер/модель використовує `/v1/responses`, використовуйте `@ai-sdk/openai`.
   - **name**: відображувана назва в інтерфейсі.
   - **models**: доступні моделі.
   - **options.baseURL**: URL-адреса кінцевої точки API.
   - **options.apiKey**: за бажанням задайте API-ключ, якщо не використовуєте автентифікацію.
   - **options.headers**: за бажанням задайте власні заголовки.

   Більше про розширені параметри — у прикладі нижче.

5. Виконайте команду `/models`, і ваш власний провайдер і моделі з'являться у списку вибору.

##### Приклад

Ось приклад задання параметрів `apiKey`, `headers` та `limit` моделі.

```json title="aigcfroge.json" {9,11,17-20}
{
  "$schema": "https://aigcfroge.ai/config.json",
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "My AI ProviderDisplay Name",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "My Model Display Name",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Деталі конфігурації:

- **apiKey**: задається за допомогою синтаксису змінної `env`, [докладніше](/docs/config#env-vars).
- **headers**: власні заголовки, які надсилаються з кожним запитом.
- **limit.context**: максимальна кількість вхідних токенів, яку приймає модель.
- **limit.output**: максимальна кількість токенів, яку модель може згенерувати.

Поля `limit` дають змогу Aigcfroge розуміти, скільки контексту у вас залишилося. Стандартні провайдери отримують ці значення з models.dev автоматично.

## Усунення несправностей

Якщо у вас виникають труднощі з налаштуванням провайдера, перевірте наступне:

1. **Перевірте налаштування автентифікації**: виконайте `aigcfroge auth list`, щоб побачити, чи додані облікові дані
   для провайдера до вашої конфігурації.

   Це не стосується провайдерів, як-от Amazon Bedrock, які покладаються на змінні середовища для своєї автентифікації.

2. Для власних провайдерів перевірте конфігурацію aigcfroge та:
   - переконайтеся, що ID провайдера, використаний у команді `/connect`, збігається з ID у вашій конфігурації aigcfroge.
   - для провайдера використовується правильний npm-пакет. Наприклад, для Cerebras використовуйте `@ai-sdk/cerebras`. А для всіх інших сумісних з OpenAI провайдерів використовуйте `@ai-sdk/openai-compatible` (для `/v1/chat/completions`); якщо модель використовує `/v1/responses`, використовуйте `@ai-sdk/openai`. Для змішаних налаштувань у межах одного провайдера ви можете змінити його для кожної моделі через `provider.npm`.
   - перевірте, чи у полі `options.baseURL` використовується правильна кінцева точка API.
